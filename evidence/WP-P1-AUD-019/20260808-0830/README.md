# WP-P1-AUD-019: 監査アンカーの外部保存

実施日: 2026-08-08 (UTC)

## 1. 出発点 — 自分で書いた限界を閉じる

[[WP-P1-AUD-018]] で書き出しと照合を作ったとき、道具の末尾にこう書いた。

> **DB の中だけで完結する照合は、DB を書ける者には破れる。**

アンカーが DB にしか無ければ、改ざんする者はイベントを書き換えたうえで
アンカーも書き換えればよい。
**外に置いて初めて、2か所を同時に偽る必要が生まれる。**

準備は揃っていた。

| もの | 状態 |
|---|---|
| `audit_anchor.external_uri` 列 | 0003 からある |
| `S3_BUCKET_AUDIT_ANCHOR` 環境変数 | 定義済み・検証済み |
| `solvi-audit-anchor` バケット | `ensure_buckets.mjs` が作る |
| 書き込み | **`persistAnchor(client, result, null)`** |

**常に null が渡されていた。** 揃っていたのに、繋がっていなかった。

## 2. 列はあったが、埋める書き込みを schema 自身が禁じていた

`audit_anchor_no_update` が**あらゆる UPDATE を拒む**。
行を入れたあとで URI を書き足すことはできない。

最初、私は「後から埋める」実装を書いた。**検査が落ちた。**

```
audit_anchor は append-only です(DELETE は許可されていません)
```

誰も書いていなかったので、この矛盾は10日以上表に出なかった。

### 順序を変えて解いた

先に外へ置き、URI を持った状態で行を入れる。
鍵は日付から決まる(`anchors/<date>.json`)ので、置く前から分かる。

**不変性を緩めない。** トリガを外す案は採らなかった —
不変であることがこの表の値である。

### 後から埋めない

既にある行(URI が null)へ外部の写しを作ることはしない。

**DB の値から作った写しは、DB が偽られていたらその偽りを写すだけ**である。
同時に書いたものでなければ、突き合わせる意味が無い。

## 3. 実際に改ざんを検知させた

不変トリガを外して DB のルートだけを書き換える — 
**DB へ書ける攻撃者**を模した。

```
改ざん前: {"status":"match","rootHash":"ae97058984ca04fd…"}
改ざん後: mismatch stored=ffffffffffff external=ae97058984ca
復元後:   match
```

**これが [[WP-P1-AUD-018]] の時点では出来なかったことである。**

## 4. 列だけを見て「置いてある」と信じない

照合は `external_uri` の有無ではなく、**実物を取りに行く**。
鍵は日付から決まるので、列は補助にすぎない。

外部の実物が消えていれば `not_uploaded` を返す。
**「一致した」とは言わない。**

## 5. ローカルでは改ざん防止になっていない

本番では Object Lock(WORM)を有効にしたバケットへ置く前提である。
ローカルの MinIO では有効化していない(`tools/ensure_buckets.mjs` が
最初からそう書いている)。

**ローカルでは「2か所に書く」だけであり、消せない保証は無い。**
効いているつもりにならないこと。

## 6. 通し確認の失敗を読み違えかけた

`audit_export_flow` が「再計算したルートがアンカーと一致する」で落ちた。
**製品の欠陥ではなかった。**

照合の道具は DB のアンカーを引くため接続情報が要る。
環境変数を渡さずに走らせており、道具は 78 で終了していた。
私の catch が `stdout` だけを出していたため、
**「環境変数が無い」が「一致しなかった」に見えていた。**

2つ直した。

- 前提が無ければ最初に落ちる(理由つき)
- 失敗の理由を捨てない(`stderr` も出す)

**失敗の理由を捨てる検査は、嘘の診断を出す。**

## 8. 残っている制約

- **ローカルに Object Lock が無い**(§5)。WORM は本番構成の話
- **この変更より前のアンカーには外部の写しが無い。** 後から作らない(§2)
- 外部保存の失敗は記録に残るが、**再試行しない。**
  URI なしで保存された日は、以後も外部の写しを持たない
- **アンカーの実体は1か所(同じ MinIO)にしかない。**
  本当の分離には別アカウント・別リージョンが要る
- 照合は worker の周回でのみ行われる。**監査人が自分で照合する経路が無い**
