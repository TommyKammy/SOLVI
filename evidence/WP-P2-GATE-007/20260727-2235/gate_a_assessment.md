## 判定: **不合格(条件付き通過も認めない)**

8条件のうち **5件達成 / 3件未達**。

**未達の3件はいずれも「実装が足りない」ではない。**
実利用者・実運用データ・本番相当環境という、**この場では調達できないもの**を必要とする。
したがって追加の実装で埋めることはできず、期日を切って人を動かす以外に道はない。

## 2. 達成した条件の中身

### GA-1: 縦切りE2E(新規に実装した)

個々の機能は各WPで確認済みだったが、**繋いだときに繋ぎ目から漏れないこと**は
未検証だった。部品単位のテストは「自分の側は正しい」を示すものであり、
事故は部品の中ではなく部品と部品の間で起きる。

1つの業務フローを通し、**依頼者の目に触れる全ての出口**を検査した。

```
依頼者が申告 → 担当者が引受 → 着手 → 内部メモ → 公開コメント → 解決 → 通知配送
```

| 出口 | 検査 |
|---|---|
| 画面(API応答) | 内部メモの文言が現れない。担当者には見える |
| 通知(送信内容) | 内部メモも公開コメントの本文も送られない。件名とリンクのみ |
| 通知(DB) | `notification` 行にも本文が無い |
| 監査 | 各段階が記録され、内部メモの本文と宛先アドレスは入らない |

内部メモには「田中さんは以前も同じ操作でミスしている。パスワード管理が甘い可能性あり。」
という、**依頼者本人に見えたら関係が壊れる**内容を入れた。
これが4つの出口すべてから出ないことを確認している。

内部メモのイベントは Outbox に積まれるが、通知側が `visibility` を見て
通知0件にする。**積まないのではなく、積んでも出ないこと**を確かめた。
積まない実装だと、将来別の経路がイベントを拾ったときに漏れる。

### GA-2: 不正遷移の拒否

`new → closed` を試み、422 で拒否されることと、
**拒否後に状態が `new` のまま**であることを確認した。
拒否したのに状態だけ動いていたら最悪である。

審査中に、`assign()` が担当者を設定するだけで状態を動かさないことを確認した。
これは意図した設計である(担当を替えても状態が勝手に戻らない)。

### GA-5: アクセシビリティ

主要4画面の要求に対し、**エラー表示の状態も含めた6画面**で violation 0。
エラー表示は最も見落とされやすい状態であり、通常表示だけでは
「入力を間違えた利用者が困らない」ことの根拠にならない。

検査器自体が違反を検出できることも、意図的な違反を注入して確認済み。

## 3. 未達の3件 — それぞれ何が必要か

### GA-4: ユーザビリティテスト

**必要なもの: 初見の利用者5名と、その時間。**

これは実装で代替できない。「分かりやすく作ったつもり」を否定する場であり、
作った人間が判定してはいけない。

axe の violation 0 は**最低限の水準を割っていない**ことしか意味しない。
読み上げ順序の妥当性、文言の分かりやすさ、迷わず送信まで到達できるかは
人が試さなければ分からない。

### GA-6: Runbook の実手順化と机上演習

| Runbook | 状態 |
|---|---|
| 08.1 デプロイ | **draft** — 実体化が必要 |
| 08.2 バックアップ・リストア | baseline。ただし [[WP-P1-BCK-007]] の実演が未実施(Gate 1 G1-8) |
| 08.3 インシデント対応 | baseline。**オンコール担当者名が空欄**(OQ-013) |

08.3 は手順として成立しているが、「誰に連絡するか」が決まっていない。
障害の最中にそれを決めることはできない。

疑似アラートの到達確認は済んでいる(発火から2分34秒、解決通知も確認)が、
**机上演習そのものは未実施**である。

### GA-8: 本番相当環境での再計測

ローカル計測はネットワーク遅延を含まないため、Gate 条件が明示的に
本番相当環境を要求している(この条件は初回レビューで追加したものである)。

本番相当環境が存在しないため測定できない。

## 5. 実装として残っているもの(参考)

Gate A の条件ではないが、パイロットで利用者が困る箇所として記録する。

- **担当者向けの操作画面が無い。** API は実装済みだが画面が無いため、
  IT担当は状態遷移・割当を画面から行えない
- **コメント・添付の画面が無い。** 依頼者は起票後に追記できず、
  やり取りは結局メールや電話に戻る
- 組織IDを利用者に入力させている。複数組織に所属する場合の切替UIが無い

**この3点が残ったままパイロットを始めると、「使ってみたが結局電話した」
という結果になり、パイロットで測りたかったことが測れない。**
Gate A の条件には無いが、実施前に判断すべき事項として挙げる。
