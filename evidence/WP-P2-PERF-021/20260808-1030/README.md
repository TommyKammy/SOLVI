# WP-P2-PERF-021: 判定件数での実測とリソース見積り

実施日: 2026-08-08 (UTC)

## 1. 前提が決まった

利用者判断により、判定の条件が確定した。

| 項目 | 値 |
|---|---|
| 月間チケット発生数 | 2,000件 |
| ピーク同時利用者数 | 50 |
| チケット保持年数 | **2年**(超過分はアーカイブ退避 → [[06.4_Backlog]] A-1) |
| **判定に用いる件数** | **48,000件** |
| 本番構成 | AWS / オンプレ Hyper-V。**リソースはスケール可能** |

スケールできるのだから、答えるべき問いが変わる。
**「この環境で何ミリ秒か」ではなく「どれだけのリソースで収まるか」。**

## 3. 仮説を4つ立てて、3つ外した

前回の報告で「Node は単一スレッドだから複数プロセスが要る」と書いた。
**測ったら違った。**

| # | 仮説 | 検証 | 結果 |
|---|---|---|---|
| 1 | データ件数が効く | 48kでSQL直接測定 | **外れ**。一覧22ms / COUNT 19ms |
| 2 | APIプロセス数が足りない | 4プロセスへ増やす | **外れ**。884ms → 997ms(改善せず) |
| 3 | ホストとVMの境界が遅い | コンテナ内から測定 | **外れ**。928ms(ほぼ同じ) |
| 4 | 接続プールが小さい(10固定) | 10/30/50 で比較 | **外れ**。928/954/978ms |

### 途中で自分の測定が無効だったことに気付いた

仮説1の最初の測定は `DATABASE_ADMIN_URL` で `app.current_org` を
設定せずに行っていた。**RLS が何も一致せず、0行を返す問い合わせを
測っていた**(2ms)。

正しく設定して測り直すと 19〜22ms。結論は変わらなかったが、
**「速い」と言った根拠は無効だった。**

## 4. 原因は CPU コア数だった

同じ問い合わせを、同時実行数だけ変えて測る。

| 同時 | p50 | p95 |
|---:|---:|---:|
| 1 | 69ms | 78ms |
| 5 | 83ms | 105ms |
| 25 | 306ms | 459ms |
| 50 | 546ms | **917ms** |

**1要求あたり 69ms。** Colima VM は 4コア。

```
同時50 × 69ms ÷ 4コア = 862ms   (実測 917ms)
```

一致する。**CPU で決まっている。**

これで仮説2が外れた理由も説明がつく。
**プロセスを増やしても、同じ4コアを分け合うだけ**である。

## 5. リソース見積り

サービス時間 69ms・同時50 を前提に、閾値 1,500ms を保つコア数。

| コア数 | 見積り | 判定 |
|---:|---:|---|
| 2 | 約1,725ms | NG |
| **3** | **約1,150ms** | **OK** |
| 4 | 約862ms(実測917ms) | OK |
| 8 | 約431ms | OK |

**APIプロセスに割り当てるCPUは4コアあれば足りる。**
3コアで理論上は収まるが、余裕が無い。

前提: サービス時間 69ms が本番でも同程度であること。
本番はコンテナ/VMの世代が違うため、**この数値は上限側の目安**である
(開発機のほうが遅いことが多い)。

## 6. 接続プールを設定可能にした

`max: 10` が**定数だった**。本番はリソースをスケールできる前提なのに、
ここだけ固定されていた。

`PG_POOL_MAX`(既定10)にした。**今回の遅さの原因ではなかった**が、
コア数を増やしたときに次の上限になる。

**プロセス数 × プール ≤ PostgreSQL の `max_connections`(既定100)** を
守ること。`.env.example` にもそう書いた。

## 7. 判定

| 対象 | 判定 |
|---|---|
| **API(素の Node)** | **48,000件・同時50・4コアで p95 917ms 〜 1,236ms。閾値内** |
| 画面(Next.js) | **判定しない。** 開発モードであり本番構成ではない |
| 承認画面 | **存在しない**(Phase 4) |

**NFR-PERF-001 は「条件付きで見通しが立った」。**
5画面のうち4画面しか無く、うち画面層は本番構成で測っていない。
ただし**リソースを増やせば収まる形であること**は示せた。
