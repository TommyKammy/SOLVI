## 1. SLAクロックの停止・再開 (FR-TKT-008)

シナリオ: 10分割当 → 20分着手 → 30分でpending → **3時間の待ち** → 210分で再開 → 240分で解決

| 項目 | 値 |
|---|---|
| 実経過時間 | 4時間(240分) |
| **SLA算入時間** | **1時間(3600秒)** |
| 差分 | 3時間の待ち時間が除外されている |

停止・再開を複数回繰り返しても正しく累積することを単体テストで確認
(10分作業 → 60分待ち → 20分作業 → 120分待ち → 15分作業 = 45分)。

### 停止条件の根拠
停止・再開の判断は状態機械の `slaClock` を唯一の根拠にした。
サービス側で独自の条件分岐を書くと、遷移表と実際の挙動が食い違う。
遷移表の全規則に対して `clockActionFor` が一致することをテストで固定している。

## 3. 検索の安全性 (TL-03 / 脅威 T-03)

| 入力 | 結果 |
|---|---|
| `'; DROP TABLE ticket; --` | 例外なし・テーブル残存 |
| `a & b \| c ! d` | 例外なし(tsquery構文として解釈されない) |
| `to_tsquery('x')` | 例外なし |
| `:*` `\` | 例外なし |
| `%`(単体) | **0件**(ワイルドカードとして解釈されない) |
| `通_の` | **0件**(アンダースコアが1文字ワイルドカードにならない) |

ILIKEのワイルドカード `%` `_` とエスケープ文字 `\` をエスケープしている。
エスケープしないと、利用者の入力が検索範囲を勝手に広げる。
