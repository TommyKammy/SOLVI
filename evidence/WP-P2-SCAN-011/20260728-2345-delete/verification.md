# 添付の削除 Evidence

- 実施日時: 2026-07-28 23:45:53 JST
- 対象: [[WP-P2-SCAN-011]] の残存制約(誤添付の取り消し手段)

## 0. なぜ必要だったか

誤って他人の情報が写ったスクリーンショットを添付した場合、
**取り消す手段が一切なかった**。情報漏えいに対して打つ手が無い状態である。

「気を付ける」で防ぐ問題ではない。人は間違えるし、間違えたことに後から気付く。
気付いたときに直せることが要る。

## 1. 設計: 実体は消すが、あったことは残す

| やり方 | 問題 |
|---|---|
| 実体を残して一覧から隠す | **削除したつもりで漏えいが続く**。署名を作れる者には依然として読める |
| 記録ごと消す | 誰が何を消したか追えず、**証拠隠滅と区別できない** |

したがって:

- **オブジェクトストレージの実体は物理削除**する
- **メタデータの行は論理削除で残す**(ファイル名も残す)
- 監査に「誰が・何を・なぜ」を記録する

ファイル名を残すのは、**何が削除されたか分からなければ監査として成立しない**ため。

## 2. 検証

`tests/security/attachment-delete.test.ts` — 14件すべて通過。

### 実体を本当に消す

| 検証 | 結果 |
|---|---|
| **削除するとオブジェクトストレージから実体が消える** | OK(実際に取得を試みて確認) |
| 削除後は一覧に現れない | OK |
| **削除後はダウンロードURLが出ない** | OK |
| 二重に削除しても壊れない | OK |

1つ目が本題である。メタデータを隠すだけの実装でも一覧からは消えるため、
**「消えたように見える」テストでは不十分**。実体の取得を直接試みて確認した。

### あったことは残す

| 検証 | 結果 |
|---|---|
| **誰が・何を・なぜ消したかが監査に残る** | OK |
| メタデータの行は残る | OK |
| **「誰が」と「なぜ」の欠けた削除を作れない**(DB制約) | OK |
| 理由が空なら 400 | OK |

理由を必須にしたのは、**「誤って添付した」と「都合の悪い記録を消した」を
後から区別できなければならない**ため。理由の無い削除は、その区別を放棄することになる。

### 誰が消せるか

| 主体 | 対象 | 結果 |
|---|---|---|
| 本人 | 自分が添付したもの | 削除できる |
| 依頼者 | **担当者の添付** | **403**(対応の記録を一方的に削れない) |
| 担当者 | 組織内の添付 | 削除できる(依頼者の誤添付に気付いて消せる必要がある) |
| 依頼者 | **内部添付** | **404**(403だと「そのIDの内部添付が存在する」と教えてしまう) |
| 他人 | 他人のチケットの添付 | 404 |

担当者が組織内の添付を消せるようにしたのは、**依頼者が誤って添付したものに
担当者が気付く**場面があるためである。本人だけが消せる設計だと、
気付いた側が「消してください」と依頼するしかない。

## 3. 実装上の判断

### 実体を先に消す

メタデータを先に消すと、実体の削除に失敗したとき
**「消えたはずのファイルが残っている」状態**になる。しかも一覧に出ないため気付けない。
実体の削除が失敗すれば、処理全体が止まる順序にした。

### 既に無い実体の削除は成功として扱う

削除は繰り返し呼ばれうる(再試行、二重クリック)。
「無いものを消せない」で失敗すると、メタデータだけ削除済みで実体が残る、
という中途半端な状態を招く。

### 削除済みはスキャン対象から外す

実体が無いため、外さないと永久に `deferred` が積み上がり、
`SolviAttachmentScanStalled` が誤って発火し続ける。

### POST で受ける

`GET` や `DELETE` をリンクに置くと、ページを開いただけで消える経路ができる。
**取り消せない操作を偶発的に起こさせない。**

### 画面では理由の入力を挟む

ボタン1つで消せると、誤操作でも消えてしまう。
`<details>` で畳み、開いて理由を書いてから押す形にした。
「削除すると元に戻せません」と文言でも明示している。

## 5. 残っている制約

- **差し替え(削除して同じ位置に新しいものを置く)は無い。** 削除してから
  改めて添付する形になる。順序を間違えると一時的に添付が無い状態になるが、
  「差し替え」を1操作にすると、失敗時にどちらの状態か分からなくなる
- 削除済みの添付を一覧で確認する画面が無い。監査ログを見る必要がある
- **オブジェクトストレージのバージョニングが有効だと物理削除が効かない。**
  本番でバージョニングを有効にする場合、削除マーカーだけでなく
  全バージョンの削除が必要になる(ローカルの MinIO では無効)
