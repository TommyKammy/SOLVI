## 2. 実体はアプリを通さない

ブラウザから**オブジェクトストレージへ直接 PUT する**。
アプリを経由させると、大きなファイルでプロセスが詰まり、
同時に何人かが送っただけで他のリクエストが待たされる。

Next.js のサーバ側は署名付きURLを発行するだけで、**ファイルの実体は通らない**。
ブラウザから直接 SOLVI API を叩かせないのは、セッションCookieが `HttpOnly` で
JSから読めず、また API のオリジンを露出させると CORS の設定が必要になるため。

**検証はURLを出す前に行う。** 出してしまってから拒否しても、実体は既に保存されている。

## 3. 発見した設計上の問題 — 内部名で署名したURLはブラウザが使えない

最初の通し確認で `getaddrinfo ENOTFOUND minio` が出た。

APIはコンテナ内部の名前(`http://minio:9000`)で署名付きURLを作るが、
**それを受け取るのはブラウザ**であり、その名前を解決できない。

これはローカル固有の問題ではない。本番でも、アプリはVPC内のエンドポイントを、
ブラウザは公開URLを使うことが多い。**SigV4 はホスト名を署名対象に含む**ため、
渡す相手が使うホストで署名しなければ、名前解決に成功しても署名が合わない。

`S3_PUBLIC_ENDPOINT` を分離した。

| 用途 | 使う接続先 |
|---|---|
| ブラウザへ渡す署名付きURL | `S3_PUBLIC_ENDPOINT`(未設定なら `S3_ENDPOINT`) |
| サーバ自身の実体取得(スキャン) | `S3_ENDPOINT` |

## 4. スキャン中を隠さない

「まだ開けません」とだけ出すと、利用者は壊れていると思って
**同じファイルを何度も送り直す**。何が起きていて、いつ開けるようになるのかを書く。

| 状態 | 表示 |
|---|---|
| `pending` | 「ウイルスチェック中 — 確認が終わるまで開けません。しばらくしてから再度ご覧ください。」 |
| `infected` | 「安全でないファイル — ウイルスが検出されたため開けません。担当者へご連絡ください。」 |
| `clean` | リンクとして表示 |

開けないファイル名は**リンクに見せない**(取り消し線)。
押しても開かないものをリンクにすると、壊れていると思われる。

開けるかどうかの判断は API が `downloadable` として返す。
画面が `scanStatus` を解釈して判断すると、状態が増えたときに画面ごとに判断が分かれる。

## 5. 署名付きURLを画面に埋め込まない

ダウンロードは `/attachments/<id>` を経由し、毎回サーバへ問い合わせる。

画面に署名付きURLを直接埋め込むと、**ページを共有したりスクリーンショットを
撮ったりしただけで、有効期限まで誰でも取得できてしまう**。
毎回問い合わせれば、その時点の権限とスキャン状態で判断できる。

リダイレクトは 302(一時)にした。恒久リダイレクトにすると、
ブラウザが期限切れのURLをキャッシュして次回開けなくなる。

## 6. スキャン滞留のアラート

`SolviAttachmentScanStalled` を追加した。

```promql
sum(rate(solvi_attachment_scans_total{outcome="deferred"}[10m])) > 0
and
sum(rate(solvi_attachment_scans_total{outcome="clean"}[10m])) == 0
```

**画面は正常に見えるが、添付が誰も開けない状態になる。**
ダウンロードURLは `clean` でなければ発行されないため、スキャナが落ちると
添付は溜まる一方になる。利用者からは「ファイルが壊れている」としか見えず、
発見が遅れる。

判定不能だけが続いている状態を検知条件にした。
`clean` が1件でも出ていれば、スキャナは生きている。

## 7. アクセシビリティ

添付欄を含む9画面で violation 0。

公開範囲の選択は `<fieldset>` + `<legend>`。
ファイル選択には説明文を `aria-describedby` で紐づけ、
「25MBまで」「実行できる形式は添付できません」を事前に伝える —
送信してから拒否されるより、送る前に分かるほうが負担が少ない。

## 8. 実装中に見つけたテストの問題

`attachment-scan.test.ts` が「既にあるチケットを1件借りる」作りになっており、
**単体では通るのに全体実行では落ちた**。他のテストファイルが
`cleanBusinessData` で全チケットを消すためである。

自前でフィクスチャを作るよう直した。同じ形の失敗は
[[WP-P2-OPSUI-010]] でも起きており、テストファイル間の依存は
繰り返し現れる問題である。
