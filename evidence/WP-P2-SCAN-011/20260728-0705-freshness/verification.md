# ウイルス定義の鮮度監視 Evidence

- 実施日時: 2026-07-28 07:05:13 JST
- 対象: [[WP-P2-SCAN-011]] の残存制約(freshclam の運用手順)

## 0. 実測で見つけた状態 — 5か月古い定義で動いていた

作業を始めた時点で、稼働中のスキャナは次の状態だった。

| 対象 | 値 |
|---|---|
| **clamd が報告する定義** | version **27927**、**2026-03-01** ビルド |
| **ディスク上の `daily.cvd`** | version **28074**、**2026-07-27** ビルド |
| 当日 | 2026-07-27 |

**約5か月古い定義で動いていた。** しかも `daily.cvd` は当日ビルドのものが
ディスクに存在していた — freshclam は正しく更新していたが、
**clamd がそれを読み直していなかった**。

## 1. なぜ気付けなかったか

この状態は「壊れている」ようには一切見えない。

| 確認手段 | 結果 |
|---|---|
| `clamdcheck.sh`(ヘルスチェック) | **OK** |
| clamd の SelfCheck ログ | **"Database status OK"** を10分おきに出力 |
| `daily.cvd` のファイル日時 | **当日**(更新されているように見える) |
| スキャン実行 | **成功**。`clean` が返る |
| EICAR の検出 | **検出できる**(古い定義にも入っているため) |

**すべて正常に見える。** 古い定義で見逃しているだけである。

これが「**検知できていないことは検知できない**」の具体例だった。
スキャナは動いており、結果も返す。返している結果が古い知識に基づくことだけが問題で、
それは外から結果を見ても分からない。

## 2. `RELOAD` では直らなかった

```
before : ClamAV 1.4.3/27927/Sun Mar  1 07:24:39 2026
reload : RELOADING
after  : ClamAV 1.4.3/27927/Sun Mar  1 07:24:39 2026
```

`RELOAD` コマンドは "RELOADING" を返すが、25秒待っても定義は変わらなかった。

**再起動で解消した。**

```
after restart: ClamAV 1.4.3/28074/Mon Jul 27 06:25:14 2026
```

この事実を Runbook に記録した。「RELOAD を試す」で止まると、
効いていないのに対処したつもりになる。

## 3. 対策 — スキャナに「何を読み込んでいるか」を聞く

**ディスク上のファイル日時を見ない。** ファイルは新しいのに動いている定義が
古い、というのが今回の状態そのものだった。

`clamd` の `VERSION` に問い合わせ、報告された定義のビルド日時から古さを算出する。

| 実装 | 内容 |
|---|---|
| `parseVersionResponse()` | `ClamAV 1.4.3/28074/Mon Jul 27 06:25:14 2026` を解釈 |
| メトリクス | `solvi_scanner_signature_age_seconds`(worker が10分ごとに更新) |
| アラート | `SolviScannerSignaturesStale`(7日超で30分継続) |
| 手動確認 | `npm run check:scanner` |

閾値を7日にしたのは、ClamAV の定義が日次で更新されるため。
数日の遅れは許容し、週を跨いだら人が確認する。

### 解釈できない応答を「新しい」ことにしない

```
'' / 'ClamAV 1.4.3' / 'ClamAV 1.4.3/abc/...' / 'version=1.4.3 signatures=28074'
  → すべて null
```

「読めなかったから新しいことにする」とすると、**応答形式が変わった日に
鮮度の監視が黙って止まる**。これまで見つけた同種の欠陥
(メトリクスの no-op、トレースの自動計装無効、署名の不一致)と同じ形である。

## 4. Runbook

`docs/ops/slo.md#ウイルス定義が古い` に、原因別の対処を書いた。

| 状況 | 対処 |
|---|---|
| ディスクも古い | freshclam が更新できていない。ネットワーク到達性を確認 |
| **ディスクは新しいが clamd が古い** | **clamd を再起動する**(`RELOAD` では直らない) |

加えて、**古い定義だった期間に `clean` と判定された添付の再スキャン手順**も
書いた。定義が古かったなら、その間の判定は信用できない。

## 6. 残っている制約

- **worker が停止しているとメトリクスが更新されない。** 古い値が残るのではなく
  観測が止まるため、`SolviScannerSignaturesStale` は発火しない。
  worker の停止自体は `SolviTargetDown` が捕まえるが、**2つのアラートを
  突き合わせないと「定義の鮮度が分からない状態」だと判断できない**
- 定義が古かった期間の添付を自動で再スキャンしない。手順は書いたが手動である
- amd64 エミュレーションでの freshclam 更新は動作したが、
  本番相当環境での挙動は未確認
