# Operations and Performance Requirements

## 適用範囲

可用性・復旧・可観測性・性能の要求正本。目標値は[[01.8_Success_Metrics]]と一致させる。

## 要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| NFR-OPS-001 | 可用性 | 営業時間内(平日8-20時JST)の正常応答率99.5%/月以上 | Should | 合成監視の月次レポートで達成(TL-15) |
| NFR-OPS-002 | 復旧 | RPO≤24時間、RTO≤4時間。DB(PITR)とAttachmentのRestore手順 | Must | Restore Drillで RPO/RTO 実測値が目標内(TL-14、G1-8) |
| NFR-OPS-003 | 可観測性 | correlation_idでPortal→API→Outbox→Worker→Executor→監査を一意に追跡 | Must | UC-012を1つのIDで再現できる(TL-12) |
| NFR-OPS-004 | オンコール/SLO | SLO定義・アラート・エスカレーション先・対応時間帯を定義し運用 | Must(Gate A前) | オンコール表と1回以上の疑似アラート対応記録 |
| NFR-PERF-001 | 画面応答 | 主要5画面(Portalトップ/申請/チケット詳細/Ops一覧/承認)p95 ≤1.5秒 @同時50ユーザ | Should | 負荷テスト結果(TL-15)。**初回実測済み・判定は保留**([[WP-P2-PERF-020]])。承認画面が未実装で4画面しか測れず、画面は開発モードでの値。50,003件・同時50で Ops一覧が 1,781ms(超過)。**効いているのは件数ではなく同時実行数** |
| NFR-PERF-002 | 検索応答 | 通常検索 p95 ≤2.0秒 @記事1万件・チケット10万件 | Should | ベンチマーク結果(TL-15) |
| NFR-PERF-003 | 非同期処理遅延 | Outbox発行→Worker処理開始の p95 ≤30秒(通常時) | Should | 計測ダッシュボード |

## 設計・検証規則

- 目標値未達時は「改善」か「目標値の合意変更(記録付き)」のどちらかを選び、放置しない。
- 性能テストは合成データで実施し、本番相当データ量の根拠を記録する。
