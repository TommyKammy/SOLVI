# Identity OIDC SCIM Requirements

## 適用範囲

認証(OIDC)・Provisioning(SCIM)・権限マッピングの要求正本。データモデルは[[02.18_Organization_Data_Model_and_RLS]]を参照。

## 要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| FR-IDM-001 | OIDC SSO | Okta(P1)/Entra(P4)でLogin。PKCE必須 | Must | issuer/audience/state/nonce/exp各不正ケースの拒否テスト全通過(G1-1) |
| FR-IDM-002 | Identity Link | issuer+subjectをUserへLink。メールは識別子にしない | Must | メール変更後も同一user_id・履歴・担当が維持される |
| FR-IDM-003 | Role Mapping | IdP Group→SOLVI Role(org scopeのみ)。未知Groupはfail closed | Must | 未知Group所属ユーザがrequester以外の権限を得ない。platform roleのマッピング登録がDB制約で拒否される |
| FR-IDM-004 | SCIM User | User作成/更新/PATCH/Deactivate/Filter | Must | §SCIM準拠マトリクスの「準拠」項目がOkta/Entra実機Contract Testで全通過 |
| FR-IDM-005 | SCIM Group | Group/Membership同期 | Should | 追加→削除→再送(再現性テスト)で最終状態が収束 |
| FR-IDM-006 | 兼務・出向 | 複数Organizationへの期限付きRoleBinding | Should | 期限到来で自動失権+監査イベント |
| FR-IDM-007 | Leaver | 退職・停止時のアクセス停止と履歴保持 | Should | deactivate後のログイン不可+チケット履歴・担当表示が保持される。**ローカル認証の範囲で達成**([[WP-P1-IDM-011]] / `/ops/users`)。予約停止(退職日での自動停止)は IdP 連携の範囲 |
| FR-IDM-008 | セッション失効 | IdP無効化/SCIM deactivate/手動停止から15分以内に既存セッション・リフレッシュトークン失効 | Must | 失効SLAテスト通過(G1-9) |
| FR-IDM-009 | SCIMトークン運用 | Bearer tokenの90日ローテーション・即時失効・平文再表示なし(生成時のみ表示) | Must | 旧トークンの失効即時反映テスト+UIに再表示機能がないこと |

## SCIM 2.0 準拠マトリクス(準拠を名乗る範囲の定義)

| 項目 | 準拠 | 備考 |
|---|---|---|
| /Users CRUD(RFC 7644 §3.2-3.6) | ✅ | |
| /Users PATCH(§3.5.2: add/replace/remove、path式は属性直指定+valueフィルタ) | ✅ | Okta/Entraが発行する形のみ。汎用path式全文法は対象外 |
| /Groups CRUD+PATCH(members) | ✅ | 大規模グループの差分PATCH前提 |
| filter(§3.4.2.2) | ⚠️ 限定 | `userName eq`・`externalId eq`のみ(Okta/Entraの照合用途)。他演算子は501 |
| /ServiceProviderConfig, /ResourceTypes, /Schemas | ✅ | Discovery必須 |
| ソート・ページネーション | ⚠️ | ページネーションのみ(startIndex/count)。sortは501 |
| ETag(§3.14) | ❌ | 非対応と明示 |
| Bulk(§3.7) | ❌ | 非対応と明示(IdP既定動作で不要) |
| /Me | ❌ | 対象外 |

- deactivateは`active: false`で表現し、DELETEは論理削除(履歴保持)として同義に扱う。
- 重複`externalId`・重複`userName`は409+SCIMエラー形式で返す。
- エンドポイント公開: 専用ホスト(例: scim.solvi.example)+IdP IPアローリスト+Bearer認証。公開インターネットへの無制限公開は禁止。

## 設計・検証規則

- Must要求は対象Gate前にEvidenceを残す。SCIMはOkta/Entra**両方の実機**でContract Testを行う(モックのみでの合格は不可)。
- JML: 入社(SCIM create)→異動(グループ変更→Role再計算)→兼務(複数binding)→休職(active=false→復職true)→退職(deactivate+失効+担当引継ぎ通知)をUATシナリオ化(WP-P5-JML-005)。
