# Migration and Audit Requirements

## 適用範囲

Freshservice移行(MIG)と監査(AUD)の要求正本。移行戦略は[[04.20_Migration_and_Cutover_Strategy]]、監査設計は[[02.17_Audit_Event_Catalog]]。

## Migration要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| MIG-001 | 移行対象確定 | 移行対象/非対象(参照保管/破棄)をオブジェクト種別・期間で確定し[[99.8_Migration_Inventory]]に実数で記録 | Must | Inventoryに全オブジェクト種の件数・期間・出典・確認日がある |
| MIG-002 | 完全性検証 | 件数照合+サンプルhash照合+必須フィールド欠落検査 | Must | 照合一致率100%(不一致は原因記録+再実行で解消) |
| MIG-003 | IDマッピング | Freshservice ID→SOLVI IDの対応表を永続保存。旧チケット番号の検索・表示、旧URLからの参照手段 | Must | 旧番号での検索がヒットする。対応表がexport可能 |
| MIG-004 | リハーサル | 本番前に最低2回のdry-run(全量)+タイム計測+差分移行手順の検証 | Must | リハーサル記録+Cutover所要時間の見積り根拠 |
| MIG-005 | Cutover/Rollback | Freshservice read-only期間の設定、切替判定基準、Rollback(Freshservice routing復帰)手順 | Must | Rollbackリハーサル1回成功 |

- 移行時の注意(要求に付随する制約): 添付は件数・総サイズを事前計測し上限方針を決める。コメントのpublic/internal区分を保持する。文字コード・改行はUTF-8/LFへ正規化し、破損レコードは隔離リストへ。法的・監査上の保持年数は[[03.16_Data_Retention_and_Privacy]]の確定値に従う。Freshservice APIのexport仕様はWP-P3-MIG-005開始時に実環境で検証する(未検証事項を前提にしない)。

## Audit要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| AUD-001 | イベントカバレッジ | [[02.17_Audit_Event_Catalog]]§2のPhase別必須イベントを全種記録 | Must | イベント種別ごとの生成テスト+カタログ照合で欠落0 |
| AUD-002 | 閲覧権限 | auditor/platform_auditorのみ閲覧可。閲覧・export自体も監査記録。管理者に削除・編集手段なし | Must | 権限外閲覧の拒否テスト+削除経路が存在しないことのコードレビュー |
| AUD-003 | Retention/Export | 保持5年(Gate 0で法務確定)+JSONL export+日次アンカー照合手順 | Should | export実行+アンカー再計算の一致。**export と照合は達成**([[WP-P1-AUD-018]] / `audit_export_flow`)。**保持5年の削除・退避とアンカーの外部保存は未実装** |
