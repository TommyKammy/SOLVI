# Acceptance Test Strategy

## 1. 概要

要求をUnit、Integration、Contract、E2E、Security、Performance、UAT、Restore Drillへ割り当てる。

## 2. 目的

- 要求とEvidenceの孤立を防ぐ
- 本番化判断を再現可能にする

## 3. 対象範囲

- Test ID
- Requirement ID
- Environment
- Precondition
- Steps
- Expected
- Actual
- Evidence
- Sign-off

## 4. 対象外

- Test件数だけで品質を判断すること

## 5. 基本方針

- **Risk based**：Identity/Executor/Auditは異常系を厚くする
- **Automate first**：反復可能検証はCIへ
- **Human validation**：UX/運用判断はHuman sign-off

## 6. 成果物

- Gate別Test Plan
- Evidence Checklist
- UAT scenario

## 7. 受入基準

- [ ] Must要求に検証が紐付く
- [ ] 失敗結果を削除せず再試験履歴を残す

## 8. リスクと対策

- **Coverage gap**：RTMでOrphan検査
- **False confidence**：Manual/UAT/Restoreを残す
