# Ticket Requirements

## 適用範囲

Incident/Service Requestの要求正本。状態機械の定義を含む。関連: [[05.3_Ticket_Core]]、[[02.17_Audit_Event_Catalog]]。

## 要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| FR-TKT-001 | チケット作成 | Request/Incidentを利用者・API・(将来)メールから作成。種別ごとに採番(`INC-`/`REQ-`+年+連番) | Must | 一意番号・作成イベント・監査記録が生成される |
| FR-TKT-002 | 状態遷移 | §状態機械の許可遷移のみ実行。禁止遷移はAPI層で拒否 | Must | 遷移表と1:1のTL-02テストが全通過。不正遷移が全経路で拒否 |
| FR-TKT-003 | 担当割当 | 担当Group/Userを設定。割当履歴を保持 | Must | 割当変更で履歴+通知が生成される([[WP-P2-GRP-015]] で Group を実装。**グループ割当では通知しない** — 購読設定が無い状態で全員へ送ると誰も読まなくなる) |
| FR-TKT-004 | コメント/内部メモ | 公開コメントと内部メモを分離 | Must | Requester視点のAPI/UI/通知/検索のいずれでも内部メモが露出しない |
| FR-TKT-005 | 添付 | 許可形式・サイズ(既定25MB)。スキャン完了まで配布不可、実行形式は拒否 | Must | 未スキャン・拒否形式のダウンロードが不可(T-15) |
| FR-TKT-006 | 検索/Filter | 番号・件名・依頼者・状態・担当・期間で検索 | Should | 権限外結果0件(TL-06) |
| FR-TKT-007 | 通知 | 主要イベントをEmail通知。失敗はRetryと可視化 | Should | 通知失敗がOps画面と`notification.failed`監査に現れる |
| FR-TKT-008 | SLA Lite | 応答/解決期限。停止条件(User待ち)でクロック停止 | Should | Clock制御テストで期待値一致 |
| FR-TKT-009 | 優先度算出 | Impact×Urgencyから優先度を決定論的に導出(AIは提案のみ) | Should | 同一入力で常に同一優先度。AI提案は`suggested`として区別表示 |
| FR-TKT-010 | 関連付け | Related Ticket(相互参照)とParent/Child(1階層のみ) | Should | 循環参照を拒否。Parent解決時にChild未解決なら警告 |
| FR-TKT-011 | Merge/重複 | 重複チケットのMerge(コメント統合・Requesterへ通知・元は`merged`終端) | Should | Merge後の元チケットが再オープン不可。監査に統合元/先が残る |
| FR-TKT-012 | Reopen | Resolved後14日以内はRequester/Agentが再開可。以降は新規起票 | Should | 15日目のReopenが拒否され新規起票へ誘導される |

## 状態機械(正本)

```
New → Assigned → In Progress → Pending(User待ち/外部待ち) ⇄ In Progress
In Progress | Pending → Resolved → Closed(Resolved後14日で自動)
New | Assigned | In Progress | Pending → Cancelled(Requester取消 or 重複)
任意 → Merged(FR-TKT-011の終端)
Resolved → In Progress(Reopen、14日以内のみ — FR-TKT-012)
```

- `Closed` `Merged` `Cancelled`は終端。終端からの遷移は不可(再開は新規チケット)。
- SLAクロックは`Pending`で停止、`In Progress`で再開(FR-TKT-008)。
- 全遷移は`ticket.transitioned`監査イベント(from/to/actor/理由)を生成する。

## 対象外(Non-Goals / MVP非採用)

- Watcher(購読者)機能 — Phase 7以降の候補。初期は関係者への明示通知のみ。
  このため**グループ宛の通知も行わない**([[WP-P2-GRP-015]])
- グループ単位のSLA — 目標時間は優先度だけで決まる
- 入れ子の担当グループ(1階層のみ)
- Problem管理・Release管理のユーザー露出([[01.5_Scope_and_Non_Goals]])
- 多階層のParent/Child(1階層に限定)
- チケットあたりの課金・工数集計

## 設計・検証規則

- Must要求は対象Gate前にEvidenceを残す。UI/API/Worker/直接URLの全経路で検証する。
- 状態遷移の実装は文字列更新でなく明示的な遷移テーブル/状態機械とし、TL-02で表と対応付ける。
