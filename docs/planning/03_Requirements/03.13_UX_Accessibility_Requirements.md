# UX and Accessibility Requirements

## 適用範囲

利用者体験とアクセシビリティの要求正本。画面仕様は[[11.2_Information_Architecture]]。

## 要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| NFR-UX-001 | 主要導線 | Portalトップからリクエスト送信/インシデント報告の開始が3クリック以内 | Must | 初見5名中4名以上がガイドなしで完了(GA-4) |
| NFR-UX-002 | Accessibility | **WCAG 2.2 レベルAA準拠を目標として宣言**。コントラスト比4.5:1以上、キーボードのみで全主要操作可能、フォーカス可視、色のみに依存しない状態表現 | Must | axe自動検査でPortal主要4画面 violation 0 + キーボード手動チェックリスト全項目通過(TL-13) |
| NFR-UX-003 | 日本語優先 | UI・通知・エラーが自然な日本語。専門用語は利用者向け画面で言い換える | Must | 日本語レビュー(IT部門外1名以上を含む)通過 |
| NFR-UX-004 | 状態表示 | Loading/Empty/権限なし/競合/期限切れ/オフラインの各状態に、次の行動を示す表示を持つ([[11.11_UI_State_and_Error_Model]]) | Should | 主要画面の状態一覧レビュー+E2Eで主要状態を再現。**部分達成**([[WP-P2-UISTATE-018]]):基盤停止・期限切れ・見つからない・権限なし・Empty は実装済みで `ui_state_flow` が実際にAPIを止めて確認。**Loading は状態コードの正しさと引き換えに見送り、オフラインと競合の共通表示は未実装** |
| NFR-UX-005 | AI表示の識別 | AI生成内容は人間の入力と視覚的に区別し、根拠(引用記事+版)を併記。AI検索と通常検索を利用者が区別できる | Must | UIレビュー+FR-AI-003のE2Eで引用表示を確認 |

## 設計・検証規則

- モックアップと本要求が矛盾する場合、**本要求とテストが正**([[11.13_Mockup_Asset_Index]]の正誤表参照)。
- 小画面対応: Portalはモバイル幅(375px)で主要導線が成立すること。SOLVI Opsはデスクトップ優先(1280px以上)とし、モバイル最適化は対象外と明示する。
