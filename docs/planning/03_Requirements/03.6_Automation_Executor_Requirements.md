# Automation Executor Requirements

## 適用範囲

このノートはAutomation Executor Requirementsの正本であり、関連Module、WP、Testの入力となる。

## 要求

| ID | Requirement | Detail | Priority | Acceptance |
|---|---|---|---|---|
| FR-AUT-001 | Automation Command | 承認済Workflowから型付きCommand | Must | スキーマ外・署名なしCommandが全件拒否される |
| FR-AUT-002 | Allowlist | Action/Resourceを許可List制御 | Must | Allowlist外のaction_type/resource_idが全件拒否され監査に残る |
| FR-AUT-003 | 冪等実行 | 同一Keyを一度だけ実行 | Must | 同一キーの並行二重配送で外部変更が正確に1回 |
| FR-AUT-004 | 事前条件 | 対象/承認状態を直前検証 | Must | 承認取消・期限切れ・snapshot hash不一致の各ケースで実行0件 |
| FR-AUT-005 | Execution Receipt | 事前/事後/外部応答を保存 | Should | Ticket画面からReceiptのpre/post状態と外部request IDが参照できる |
| FR-AUT-006 | Retry/Timeout | 一時障害を制御Retry | Should | 5分類のエラーが期待どおり分類され、unknownが自動Retryされない |
| FR-AUT-007 | Dry Run | 外部変更なしPolicy検証 | Should | Dry Runと本番のPolicy評価が同一コードパスであることをテストで証明 |
| FR-AUT-008 | Okta Group | 許可済Group追加/削除 | Should | Oktaテストテナントで追加・削除が成功しReceiptに外部request IDが残る |
| FR-AUT-009 | Entra Group | 許可済Group追加/削除 | Should | Entraテスト環境で追加・削除が成功しReceiptに外部request IDが残る |

## 設計・検証規則

- Must要求は対象Gate前にEvidenceを残す。
- UIだけでなくAPI、Worker、直接URL、外部APIを含めて検証する。
- Should要求を延期する場合は理由、代替策、再評価時期を記録する。
