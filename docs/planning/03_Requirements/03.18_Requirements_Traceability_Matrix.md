## Status 欄について

**この欄は手で書かない。** `tools/check_traceability.mjs` が導出し、
記載と食い違えば `check:all` が落ちる。

手で書いていた頃、WPを28件完了し検査が1352件通っている時点でも
93行のうち92行が `Not tested` のままだった。
**何が検証済みかを知るための台帳が、それを知る役に立っていなかった。**
書き換える人が居なければ、台帳は「最後に誰かが気にした日」で止まる。

| 値 | 意味 |
|---|---|
| `検査あり (Nファイル)` | 完了したWPが担い、**N個の検査ファイルが要求IDを名指ししている** |
| `実装済み・検査の名指し無し` | 完了したWPが担うが、要求IDを書いた検査が無い |
| `検査のみ(WP未完)` | 検査は名指しするが、担うWPがまだ完了していない |
| `未着手` | 完了したWPが無く、名指しする検査も無い |

> [!warning] 「検査あり」は要求を満たしている証明ではない
> 導出できるのは「**検査が要求IDを名指ししている**」までである。
> 名指しは人が書く。書き忘れれば「名指し無し」になるし、
> 見当違いの検査に名前を書いても機械には分からない。
> **この仕組みは台帳の鮮度を保つのであって、品質を保証しない。**

Work Package 欄も同様に、WPノートの `requirement_ids` と
双方向で突き合わせる(`--write` で両側を揃える)。
