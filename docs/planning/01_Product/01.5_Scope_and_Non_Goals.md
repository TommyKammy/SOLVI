# Scope and Non-Goals

## 1. 方針

Freshserviceで**実際に使っている機能**と、それを安全に自動化するために必要な基盤だけを作る。使っていない機能は作らない。追加要求はPhaseとGateを明示せずにスコープへ入れない。

## 2. スコープ(Phase割当)

| 領域 | 内容 | Phase |
|---|---|---|
| プラットフォーム基盤 | Organization/RLS、OIDC、監査、可観測性、CI、バックアップ | P1 |
| チケット管理 | Incident / Service Request、状態機械、担当、コメント/内部メモ、添付、検索、SLA Lite、通知 | P2 |
| ユーザーポータル | リクエスト送信・障害報告・進捗確認・FAQ検索・お知らせ | P2 |
| ナレッジ管理 | 記事ライフサイクル、版管理、公開範囲、日本語全文検索、チケット連携 | P3 |
| AI支援(限定) | 根拠付き回答案のPoC | P3 |
| サービスカタログ | カタログ項目、フォーム定義とその版管理、申請スナップショット | P4 |
| 承認 | 多段・並列・代理・期限、自己承認防止、SoD、再承認、承認取消 | P4 |
| 特権自動化 | Workflow/Outbox、SOLVI Run、Okta/Entraグループ操作(低リスク) | P4 |
| SCIM 2.0 | User/Group Provisioning(準拠範囲は[[03.7_Identity_OIDC_SCIM_Requirements]]で限定) | P5 |
| 資産管理(CMDB Lite) | Asset/CI、CSV取込、Reconciliation、Intune/Graph同期、関係 | P6 |
| 変更管理 | Change種別、計画項目、承認/CAB、カレンダー、PIR | P7 |
| AI高度化 | 分類・要約、RAG、Injection防御、評価、Kill Switch | P8 |
| 移行・本番判断 | Freshservice移行、並行稼働、運用移管、Gate C判断 | P9 |

## 3. Non-Goals(作らないと決めたもの)

### 恒久的に作らない

| 項目 | 理由 |
|---|---|
| ServiceNow相当の全機能再現 | 使っていない機能に投資しない |
| 汎用ローコードWorkflowデザイナー | 承認チェーンは宣言的設定で足りる。設計・セキュリティのコストが見合わない(DEC-004) |
| 独自の端末インベントリエージェント | 配布・署名・更新・脆弱性対応の永続負債([[ADR-0014_No_Custom_Inventory_Agent]]) |
| 外部顧客向けSaaSとしての提供 | 社内基盤として設計している(マルチテナントの要件が異なる) |
| ローカルパスワード認証 | 認証はIdPへ委譲([[ADR-0004_External_Identity_OIDC]]) |
| AIによる自律的な承認・実行 | [[ADR-0007_AI_Advisory_Only]] |
| 特権操作の自動Compensation | 承認なき逆操作を作らない([[02.16_Executor_Command_Contract]]§6) |

### 初期スコープ外(将来の候補。要求として起票しない)

| 項目 | 扱い |
|---|---|
| Problem管理 | 初期は利用者に露出しない。必要になればPhase 7以降で検討(DEC-003) |
| Release管理 | 同上(DEC-003) |
| Watcher(チケット購読者) | MVP非採用。関係者への明示通知で代替(DEC-006) |
| 契約・購買・プロジェクト管理 | 別システムの領域 |
| モバイルネイティブアプリ | Portalのレスポンシブ対応で代替 |
| 高度な課金・SLA契約管理 | SLA Liteで開始 |
| 多階層のParent/Child | 1階層に限定([[03.3_Ticket_Requirements]]) |
| 子Organizationの閲覧継承 | 初期は完全分離(RA-03) |

## 4. スコープ追加の手順

1. 要求として[[03.1_Requirements_Baseline]]へ起票する(IDを採番)。
2. どのPhaseで実装するかを決め、WPを作成して[[06.0_WorkPackage_Register]]へ登録する。
3. [[03.18_Requirements_Traceability_Matrix]]へ追跡行を追加する。
4. 既存Phaseの期間・Gate条件への影響を[[04.1_Master_Roadmap]]で評価する。

この4点を経ずにスコープへ入れない。「ついでに実装する」を認めない(AGENTS.md §2.3)。
