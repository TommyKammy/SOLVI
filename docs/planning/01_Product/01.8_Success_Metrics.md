# Success Metrics

## 1. 方針

導入判断(Gate A/B/C)を機能完成数でなく成果指標で行う。**Phase 0でFreshservice現状値をベースライン取得**(担当: Product Owner、期限: Gate 0まで、出典: Freshserviceレポート+担当者ヒアリング)し、以後同一定義で計測する。

## 2. 指標と目標値

| 指標 | 定義 | 目標(Gate C判定値) | 計測方法 |
|---|---|---|---|
| Task completion | 初見ユーザがガイドなしでRequest/Incident送信を完了する率 | ≥80%(5人中4人) | ユーザビリティテスト(GA-4) |
| Search self-resolution | 検索/FAQ閲覧後にチケットを起票せず解決した率 | ベースライン比+20% | 検索ログ+起票率 |
| First response time | 起票→初回応答の中央値 | ≤4営業時間(現行値以下) | チケットデータ |
| Resolution time | 起票→解決の中央値 | 現行値以下 | チケットデータ |
| Automation success | 承認済み自動化の初回成功率 | ≥99%(失敗は全件Runbook処理) | Execution Receipt集計 |
| Duplicate execution | 外部二重実行件数 | **0件(絶対)** | Receipt+外部監査ログ照合 |
| Evidence completeness | 特権実行のうちApproval〜Receiptが相関IDで完全追跡できる率 | **100%(絶対)** | UC-012サンプリング監査 |
| Agent effort | 担当者のチケットあたり処理時間 | 現行比 同等以下(悪化でGate C不合格 — RISK-009) | 時間計測サンプリング |
| CSAT | 解決時アンケート(5段階) | ≥4.0 | Portal内アンケート |
| TCO | 12か月総保有コスト(infra+AI+保守工数換算) | [[10.10_Build_vs_Buy_TCO]]の実測でFreshservice継続比を明示 | 費用実績+工数記録 |
| SLO(可用性) | 営業時間内の正常応答率 | ≥99.5%/月 | 合成監視 |

## 3. ゼロトレランス

重大越権(Cross-org漏えい)・無承認/二重実行・証跡欠落は**累計0件**がGate B/Cの前提。1件でも発生した場合は原因究明とGate再判定まで特権自動化を停止する。
