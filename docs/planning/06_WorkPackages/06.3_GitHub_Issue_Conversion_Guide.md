# GitHub Issue Conversion Guide

`status: baseline`のWPのみをIssue化する。`draft`のWPはIssueにしない([[00.4_Document_Governance]])。

## 1. 変換手順

1. [[06.0_WorkPackage_Register]]で対象Phaseの`status: baseline`のWPを抽出する。
2. 依存関係の**浅い順**にIssueを作成する(依存先のIssue番号が必要なため)。
3. WP本文をIssue bodyへ転記する(§1〜§13)。
4. `Depends on`のWP IDを、作成済みIssueの番号(`#123`)へ置換する。
5. Milestone(Phase)とProjectボードへ登録する。

## 2. Issue の書式

**Title**: `[WP-P4-EXEC-004] Executor契約・署名検証・Policy評価`

**Labels**:

| 種別 | 値 |
|---|---|
| 種類 | `wp` |
| Phase | `phase:p0` 〜 `phase:p9` |
| Workstream | `stream:gov` `stream:arch` `stream:sec` `stream:data` `stream:idm` `stream:aud` `stream:exec` `stream:scim` ほか |
| Risk | `risk:low` `risk:medium` `risk:high` `risk:critical` |
| 追加 | `needs-security-review`(Identity/Security/Executor/Migration系に必須)、`blocked`(依存未完了時) |

**Body**: WPの§1 Purpose 〜 §13 Execution Log をそのまま。加えて先頭に以下を置く。

```markdown
> 正本: `docs/planning/06_WorkPackages/<Phase>/<WP-ID>.md`
> 本Issueと正本が食い違う場合は**正本が優先**。変更は正本に反映してからIssueを更新する。
```

## 3. ブランチとPR

- ブランチ: `wp/<WP-ID>`(例: `wp/WP-P4-EXEC-004`)。1WPで複数PRに分ける場合は `wp/<WP-ID>-a` のように連番を付ける。
- PRタイトル: `[<WP-ID>] <変更内容>`
- PR本文に含めるもの:
  - `Closes #<Issue番号>`(WPの全PRが完了する最後のPRのみ)
  - §7 Acceptance Criteriaのチェックリストと充足状況
  - 実行した検証コマンドと結果
  - Migrationの有無とロールバック方法
  - セキュリティ影響(なければ「なし」)
  - Evidenceの保存先
  - UI変更がある場合はスクリーンショット(AGENTS.md §1.15)
- **複数のWPを1つのPRに混ぜない**(AGENTS.md §1.11)。

## 4. CODEOWNERS

以下のパスはSecurity Reviewerのapproveを必須にする。

```
/services/executor/            @security-reviewer
/services/api/src/common/authz/ @security-reviewer
/services/api/src/modules/audit/ @security-reviewer
/services/api/src/modules/auth/  @security-reviewer
/db/migrations/               @security-reviewer @tech-lead
/.github/workflows/           @tech-lead
/infra/                       @tech-lead
```

## 5. Issue のクローズ条件

WPの§12 Definition of Doneをすべて満たし、Execution Logへ結果を追記してからクローズする。テストが落ちている、Evidenceがない、必要なsign-offがない状態でクローズしない。

## 6. Phase 0 Issue Pack

Phase 0の6WPは依存の浅い順に以下で作成する。

1. WP-P0-GOV-001(依存なし)
2. WP-P0-ARCH-002(← 1)
3. WP-P0-SEC-003(← 2)
4. WP-P0-REQ-004(← 1, 2, 3)
5. WP-P0-DEV-005(← 2, 4)
6. WP-P0-UX-006(← 1, 4)
