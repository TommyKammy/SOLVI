## 1. 概要

Catalog選択、必要情報、確認、送信、Approval状況を段階表示。

## 2. 目的

- Request Flowを実装・検証可能にする

## 3. 対象範囲

- Category/Search
- Form
- Review
- Submit
- Status

## 4. 対象外

- 長い一画面Form

## 5. 基本方針

- **Role-specific**：PortalとOpsの情報密度を分ける
- **Consistency**：Token/Common componentを利用
- **Accessibility**：Keyboard/Focus/ErrorをAcceptanceへ

## 6. 成果物

- Screen requirement
- State inventory
- Mock/Prototype
- E2E/UAT scenario

## 7. 受入基準

- [ ] 主要TaskとStateが網羅
- [ ] 用語がSOLVIと一致
- [ ] Accessibility観点がある

## 8. リスクと対策

- **Information overload**：Primary actionを上位固定
- **Mock drift**：Requirement/Testを実装正本とする
