# UI Roadmap and Usability Test

## 1. 概要

Mock→Click prototype→Implementation→5名Test→Pilot→Improveの順で進める。

## 2. 目的

- UI Roadmap and Usability Testを実装・検証可能にする

## 3. 対象範囲

- Task success
- Time
- Misclick
- SUS/CSAT
- Qualitative feedback

## 4. 対象外

- DeveloperだけのUI承認

## 5. 基本方針

- **Role-specific**：PortalとOpsの情報密度を分ける
- **Consistency**：Token/Common componentを利用
- **Accessibility**：Keyboard/Focus/ErrorをAcceptanceへ

## 6. 成果物

- Screen requirement
- State inventory
- Mock/Prototype
- E2E/UAT scenario

## 7. 受入基準

- [ ] 主要TaskとStateが網羅
- [ ] 用語がSOLVIと一致
- [ ] Accessibility観点がある

## 8. リスクと対策

- **Information overload**：Primary actionを上位固定
- **Mock drift**：Requirement/Testを実装正本とする
