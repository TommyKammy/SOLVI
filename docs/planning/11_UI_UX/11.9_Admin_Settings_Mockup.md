# Admin Settings Mockup

## 1. 概要

SSO/OIDC、SCIM、ロールと権限、承認ポリシー、外部連携、AIをタブとカードで整理した管理設定画面。危険な操作には確認と監査を伴わせる。

## 2. 画面の構成

| 領域 | 内容 | 権限 |
|---|---|---|
| 全般 | 組織名、タイムゾーン、言語、既定チケット状態、保守モード | org_admin |
| SSO/OIDC | プロバイダ、issuer、client id、各エンドポイント、接続テスト | platform_admin |
| SCIM | ベースURL、テナント、認証方式、**トークン(生成時のみ表示)**、接続テスト | platform_admin |
| ロールと権限 | IdPグループ→SOLVIロールのマッピング | platform_admin |
| 承認ポリシー | 既定承認フロー、承認期限、期限切れ時の動作、高リスク閾値 | org_admin |
| 外部連携 | Graph / Okta / Webhook の設定と最終同期時刻 | platform_admin |
| AI設定 | 有効/無効、利用機能、モデル、データ取扱 | platform_admin |
| 監査ログ | 参照のみ | auditor |

## 3. 危険操作の扱い

| 操作 | 必要な確認 |
|---|---|
| 保守モードの有効化 | 影響説明 + 確認ダイアログ + 監査イベント |
| SCIMトークンの再生成 | 確認ダイアログ + 既存トークンの失効説明 + 監査イベント |
| ロールマッピングの変更 | 影響ユーザ数の表示 + 確認 + 監査イベント。**platform scopeのロールは選択肢に出さない** |
| 緊急変更の承認簡略化 | 二重確認 + platform_admin限定 + 監査イベント |
| 外部連携の無効化 | 影響する自動化の一覧表示 + 確認 |

## 4. 対象外

- Secretの平文再表示(生成時のみ表示。FR-IDM-009)
- Allowlistのファイル/環境変数による設定([[02.16_Executor_Command_Contract]]§2により画面+二重承認のみ)

## 5. 受入基準

- [ ] 各設定項目の閲覧・変更権限が[[02.18_Organization_Data_Model_and_RLS]]のロールと一致する
- [ ] Secret/Tokenが再表示できない
- [ ] 危険操作に§3の確認と監査イベントがある
- [ ] キーボードのみで全設定操作が可能である(NFR-UX-002)

## モックアップ正誤表(実装時は本表が優先)

`assets/ui/`のモックアップは**採用したコンセプト**であり、実装仕様の正本ではない。以下の点はモックと要求が食い違っており、**要求とテストが正**である(NFR-UX系、[[03.13_UX_Accessibility_Requirements]])。

| # | モック上の表示 | 実装時の扱い | 根拠 |
|---|---|---|---|
| E-1 | サイドバーの「問題管理」「リリース管理」 | **実装しない**(初期スコープ外) | [[01.5_Scope_and_Non_Goals]] DEC-003 |
| E-2 | SCIM設定のベースURL `neodesk.example.com`、「NeoDeskロール」の表記、テナントID `nd-tenant-001` | 旧仮称の残存。実装では**SOLVI表記**を使う | [[01.10_Naming_and_Brand]] |
| E-3 | SCIMトークン欄の表示(目のアイコン)ボタン | **実装しない**。トークンは生成時のみ表示し、再表示不可 | FR-IDM-009 |
| E-4 | 「緊急変更の承認を簡略化(CAB承認をスキップ)」トグル | 1クリックで到達させない。二重確認+権限制限+監査イベントを必須にする | FR-CAT-010、[[02.17_Audit_Event_Catalog]] |
| E-5 | サンプル会社名「ネオファーマ株式会社」、メールドメイン、2024年の日付 | 表示用のサンプル。実装要件ではない | [[11.13_Mockup_Asset_Index]] |
| E-6 | AI提案と人間の入力の視覚的区別が不明確 | AI生成内容は明示的に区別し、引用(記事+版)を併記する | NFR-UX-005 |
