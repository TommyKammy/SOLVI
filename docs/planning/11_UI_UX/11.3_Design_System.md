# Design System

> [!note] status: baseline(2026-11-18 Product Owner承認)
> UI v2のデザイントークンの正本。[[WP-P2-UIX-044]]〜[[WP-P2-UIX-046]] と同時にbaselineとした。

## 1. 概要

UI v2の見た目の正本。白を基調にして影を使わず、1pxの線で区切る。左サイドバーは**薄いブルー**にし、SOLVIを識別する色とする。
見本は `assets/ui/SOLVI_UI_v2_Mockup.html` である。見本と本書が食い違う場合は本書を正とする。

各WPは本書のトークン名を参照する。値をWPやコードへ書き写して独自に変えない。

## 2. 対象範囲

- 色(ライト/ダーク)
- 文字
- 角丸・線・余白
- アプリシェルの寸法
- 状態の表し方(期限・優先度)
- テーマ切替

## 3. 対象外

- 個別画面の情報配置(各WPで定める)
- 他社製品のロゴ・名称・画像の利用
- Webフォントの読み込み([[WP-P2-SEC-025]] のCSPを緩めないため)

## 4. 色トークン

| Token | Light | Dark | 用途 |

- 文字色と背景色の組み合わせは、両テーマでWCAG 2.2 AAのコントラスト比(本文4.5:1)を満たすこと。満たさない組み合わせが見つかったら、本書の値を直してから実装する。
- 色だけで意味を伝えない。期限超過・優先度は文字でも示す。
- 左サイドバーの件数は通常 `--side-muted`(強調は `--side-brand`、期限超過は `--danger`)で表すが、**ホバー・フォーカス・現在地の行では `--side-ink` にする。** `--side-muted` は `--side-hover`・`--side-current` の上で4.5:1を満たさないためである(2026-11-18 Product Owner決定)。

## 5. 文字

- フォント: `"Hiragino Kaku Gothic ProN", "Noto Sans JP", "Yu Gothic UI", system-ui, sans-serif`(端末にあるものを使う)
- 本文13px。補足12px。見出しは14px(上部バー)、16px(カード)、22〜24px(ページ)
- 太さは400/500/700の3段階
- 数字の列は `font-variant-numeric: tabular-nums` で桁を揃える

## 6. 形と寸法

| 項目 | 値 |
|---|---|
| 角丸 | 6px(行・ボタン)、8px(切替)、10px(カード) |
| 影 | 使わない |
| 線 | 1px、`--line`(サイドバー内は `--side-line`) |
| 左サイドバー | 幅256px |
| 上部バー | 高さ56px |
| 本文の左右余白 `--fs-content-gutter` | 各32px。ビューポート幅1100px以下では24px、600px以下では20px |
| 本文枠の最大幅 `--fs-content-max` | 1536px。左右余白を含めて本文枠をコンテンツ領域の中央に配置する |

2026-11-19に採用したモックアップの本文寸法。担当者側の業務シェル（[[WP-P2-UIX-048]]）と、依頼者ポータルのホーム・自分の問い合わせ一覧・報告・詳細（[[WP-P2-UIX-049]]）で同じトークンを使う。ポータルの共通ヘッダーは本文枠の左右に揃える。

## 7. テーマ切替

- 初期値はOSの設定(`prefers-color-scheme`)に従う。
- 利用者が選んだテーマはブラウザに保存する。読み書きに失敗しても表示は壊さない。
- サーバーには保存しない(端末ごとの設定)。
- ダークテーマは、まずアプリシェルと本書のトークンを使う部分に適用する。各画面のCSS Modulesに残る固定色は、後続WPでトークンへ置き換える。

## 8. 受入基準

- [ ] §4のトークンがすべてCSS変数として定義されている
- [ ] 両テーマでコントラストの検査が通る
- [ ] 外部フォント・外部CSSを読み込まない
