# UI State and Error Model

> [!note] この文書は実装のあとに書かれた
> 骨子のみの draft のまま [[WP-P2-UISTATE-018]] と [[WP-P2-UISTATE-020]] が
> 実装され、**実装が先行した**。ここに書いてあるのは設計の意図ではなく、
> **実際にそう作ったもの**である。先に書けなかったことは記録として残す
> ([[04.23_Wiring_Verification]] §15)。

## 1. なぜこの文書があるか

`NFR-UX-004` は「Loading / Empty / 権限なし / 競合 / 期限切れ / オフラインの
各状態に、**次の行動を示す表示**を持つ」と定める。

「次の行動を示す」が要点である。
**「エラーが発生しました」で終わる画面は、利用者を止めるだけ**であり、
状態を表示したことにならない。

## 2. 状態の一覧

| 状態 | どこで判定するか | 画面 | 次の行動 |
|---|---|---|---|
| 通常 | — | 各画面 | — |
| Empty(0件) | サーバ | `.empty` の文言 | 条件を変える / 起票する |
| 権限なし | `requireAccess` | 403 の文言 | 管理者へ連絡 |
| **見つからない** | `notFound()` | `not-found.tsx` | 一覧へ戻る |
| **期限切れ** | `requireSession()` | `/login?expired=1` | ログインし直す |
| 組織未選択 | `requireSession()` | `/select-organization` | 組織を選ぶ |
| **基盤が落ちている** | `requireSession()` | `/unavailable` | 待つ |
| **オフライン** | ブラウザ | `OfflineNotice` | 回線を直す |
| **競合** | `assertFresh()` | `?stale=1` の告知 | 読み直して考え直す |
| 画面遷移中の例外 | React | `error.tsx` | もう一度 / 最初の画面へ |
| 読み込み中 | — | **無し**(§6) | — |

太字は [[WP-P2-UISTATE-018]] / [[WP-P2-UISTATE-020]] で追加したもの。

## 3. 判定は1か所に置く

状態の判定を各画面が個別に行うと、**新しい画面を足した人が書き忘れる。**

- 認証・組織・基盤の到達性 → `requireSession()`
- 見ていた版の新しさ → `TicketService.assertFresh()`
- 権限 → `requireAccess()` / `requireRole()`

画面がやるのは**文言を出すこと**だけである。

## 4. 「失敗」を種類で分ける

同じ失敗に見えるものでも、**利用者がとるべき行動が違えば別の状態**である。

### 4.1 認証まわり

| 種類 | 意味 | すべきこと |
|---|---|---|
| 401(Cookie無し) | まだ入っていない | ログインする |
| 401(Cookie有り) | 期限切れ・失効 | ログインし直す(**理由を伝える**) |
| 組織未選択 | まだ組織を決めていない | 選ぶ |
| **5xx** | **こちらの都合で答えられない** | **待つ** |

**5xx だけは利用者の側に打つ手が無い。**
これを401と同じ扱いにすると、打つ手が無いのに
「あなたの入力が悪い」と言うことになる(→ [[99.4_Decision_Log|DL-036]])。

### 4.2 409 の2種類

| 種類 | 例 | すべきこと |
|---|---|---|
| 業務規則の競合 | 「その記号のグループは既にある」 | 入力を変える |
| **見ていた内容が古い**(`/stale`) | 他の人が変更した | **読み直して考え直す** |

同じ型にまとめると、画面は「競合が発生しました」としか言えない。

### 4.3 接続できない2種類

| 種類 | 誰が落ちているか | すべきこと |
|---|---|---|
| `/unavailable` | サービス側 | 待つ |
| オフライン | 手元の回線 | **自分で直せる** |

## 5. 文言の規則

- **日本語で書く**(NFR-UX-003)。既定のエラー画面は英語である
- **何が起きたかではなく、何ができるかを書く**
- **出口を必ず用意する。** 再試行しか無い画面は、直らないときに行き止まりになる
- **内部の詳細を出さない。** ホスト名・ポート・スタックトレースは偵察の材料になる
- **色だけに頼らない**(NFR-UX-002)。文言そのものが状態を語る
- 誤解を招く断定をしない。例:見つからない画面で「存在しません」と書かない
  — 他組織のチケットも404で返す設計(存在の秘匿)を裏切る

## 6. 読み込み中の表示を持たない

`loading.tsx` を置くとそのセグメントはストリーミングになり、
**404も500も 200 で返る。**

利用者にとっては改善だが、**合成監視にとっては失明である。**
「見つからない」を 200 で返す画面は、壊れていることを検知できなくする。

状態コードの正しさを取り、読み込み中の表示は入れていない。
→ [[99.4_Decision_Log|DL-038]]

## 7. 検証

| 検査 | 対象 |
|---|---|
| `tests/unit/require-session.test.ts` | 認証まわりの分岐(9件) |
| `tests/security/ticket-concurrency.test.ts` | 競合(10件) |
| `tools/e2e/ui_state_flow.mjs` | 26項目。**実際にAPIを停止する** |
| `tools/check_accessibility.mjs` | 状態表示3画面を含む16画面 |

**異常系は、異常を起こして確かめるしかない。**
最初に採った実装(例外を投げて `error.tsx` に出させる)は
コードを読む限り正しく見え、文言も日本語で書けていたが、動かなかった。
→ [[99.4_Decision_Log|DL-037]]

## 8. 未達

- **読み込み中の表示**(§6 の判断による)
- 競合の検出は作業画面の4操作だけ。コメント・添付・関連付けは対象外
- **どこが変わったかを示さない。** 「他の人が変更しました」とだけ言う
- 依頼者の画面には競合の検出が無い
- Partial(一部だけ取得できた)の共通表現が無い
