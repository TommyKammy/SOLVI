# UI Strategy

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**Phase 2着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

利用者向けは情報量を削減し、管理者向けは処理効率を高める二層UI。

## 2. 目的

- UI Strategyを実装・検証可能にする

## 3. 対象範囲

- Portal：検索、Request、Incident、FAQ、進捗
- Ops：Dashboard、Queue、Detail、Settings

## 4. 対象外

- 利用者にAsset/Change/SLA等の管理Menuを常時表示

## 5. 基本方針

- **Role-specific**：PortalとOpsの情報密度を分ける
- **Consistency**：Token/Common componentを利用
- **Accessibility**：Keyboard/Focus/ErrorをAcceptanceへ

## 6. 成果物

- Screen requirement
- State inventory
- Mock/Prototype
- E2E/UAT scenario

## 7. 受入基準

- [ ] 主要TaskとStateが網羅
- [ ] 用語がSOLVIと一致
- [ ] Accessibility観点がある

## 8. リスクと対策

- **Information overload**：Primary actionを上位固定
- **Mock drift**：Requirement/Testを実装正本とする
