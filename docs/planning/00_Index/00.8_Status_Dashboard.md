## 2026-07-28 の横断点検

「設定は存在し、テストは緑で、外から見て何も壊れていないが、**動いていない**」
という形の欠陥が**15件**見つかっている([[04.23_Wiring_Verification]])。
うち4件は 2026-07-28 の点検で発見し、以降は要求台帳との突き合わせと
検査の粒度を下げたことで見つかっている。

15件目(`deactivateUser` の経路が無い)は**最も実害が直接的だった** —
他は「見えない」「効かない」だったが、これは開いたままの扉である。
検査は既に見つけており、承知リストに理由付きで置かれていた。
**承知リストには「繋がないと何が起きるか」も書くことにした**(DL-030)。

| 欠陥 | 影響 |
|---|---|
| 通知の仕組みが本番経路から切り離されていた | **通知は一度も送られていなかった** |
| 監査アンカーが一度も実行されていなかった | **改ざん検知が働いていなかった** |
| 鮮度アラートが存在しないメトリクス名を参照 | 永久に発火しない |
| ログの表題が付加フィールドに上書きされる | 表題で検索できない |

`npm run check:unwired` を `check:all` に組み込み、以後の再発を機械検査で捉える。

**未接続と分かったうえで残しているもの**(検査出力に毎回現れる):
Webhook署名一式(受け口が無い)/ `assertCanSwitchOrganization`。
`isDerivedPriority` は [[WP-P2-PRIO-013]] で繋いだため一覧から外した。
`RelationService` は [[WP-P2-RELUI-012]] で繋いだため一覧から外した。

その追補の通し確認で、さらに2件が見つかっている。

| 欠陥 | 影響 |
|---|---|
| `merge` が一意制約違反をJSで握り潰していた | **「先に関連付けてから統合」が必ず500** |
| テストがシードの資格情報を全消ししていた | テスト後は全員401。認証の不具合に見える |
| `auto_close` を実行する者が居なかった | **チケットが永久に完了しない**。しかも手動ボタンとして出ていた |
| SLAの期限がどの画面にも出ていなかった | **次に何をやるべきかが分からない**。放置されたものだけ超過判定が更新されない |
| 初回応答が記録されていなかった | 応答SLAは全件が「未応答」判定 |
| **画面の絞り込みが一つも効いていなかった** | プルダウンは動きURLも変わるが、**結果だけが変わらない** |
