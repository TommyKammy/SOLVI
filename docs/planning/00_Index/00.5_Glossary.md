# Glossary

利用者向け画面では、この表の「利用者向けの言い方」を使う。管理概念を一般社員に見せない([[01.3_Product_Principles]])。

## 製品・コンポーネント

| 用語 | 定義 |
|---|---|
| SOLVI | 製品全体の名称 |
| SOLVI Portal | 一般社員向け画面(検索・リクエスト・インシデント報告・進捗確認) |
| SOLVI Ops | IT担当・管理者向けの業務コンソール |
| SOLVI Assist | AIによる分類・検索・要約・回答案・リスク案の提示機能 |
| SOLVI Run | 承認済みの特権操作を実行する分離されたExecutor |
| Core API | 業務ロジックと認可を担う中核サービス(モジュラーモノリス) |
| Worker | Outboxを読み、非同期処理・外部連携を行うプロセス |

## 業務概念

| 用語 | 定義 | 利用者向けの言い方 |
|---|---|---|
| Request | 計画可能な申請(アクセス権、ソフトウェア、機器) | リクエスト／申請 |
| Incident | サービスの中断・品質低下・利用不能の報告 | 障害／不具合の報告 |
| Ticket | RequestとIncidentの内部的な総称 | (見せない。「申請」「報告」と呼ぶ) |
| Service Catalog | 申請可能な項目の一覧 | サービスカタログ |
| Catalog Item | カタログの1項目。フォーム定義を持つ | 申請メニュー |
| Form Definition | 申請フォームの項目定義。バージョン管理される | (見せない) |
| Approval | 申請に対する承認判断 | 承認 |
| Approver | 承認者 | 承認者 |
| Delegation(代理承認) | 期間を限って他者に承認を委任すること | 代理承認 |
| Knowledge Article | ナレッジ記事。Draft/Review/Published/Retiredの版を持つ | FAQ／ナレッジ |
| Announcement | IT部門からの周知 | お知らせ |
| Asset | 管理対象の資産(PC、サーバ、ライセンス等) | 資産 |
| CI (Configuration Item) | 構成要素。Asset同様に扱うが関係(依存)を持つ | 構成情報 |
| CMDB Lite | 初期スコープに限定した資産・CI・関係の管理 | — |
| Change | 計画された変更。Standard / Normal / Emergencyの3種 | 変更 |
| CAB | Change Advisory Board。変更を審議する会議体 | 変更審査会 |
| PIR | Post Implementation Review。変更実施後の振り返り | 実施後レビュー |
| Problem | 複数インシデントの根本原因(**初期スコープ外**) | — |
| Release | リリース管理(**初期スコープ外**) | — |

## 優先度・SLA

| 用語 | 定義 |
|---|---|
| Impact | 影響範囲の大きさ(何人・どの業務が止まるか) |
| Urgency | 緊急度(いつまでに解決が必要か) |
| Priority | ImpactとUrgencyから決定論的に導出される優先度(FR-TKT-009) |
| SLA | 応答・解決の目標時間。SOLVIでは簡易版(SLA Lite)を実装 |
| SLA Clock | SLAの経過時間。`Pending`(利用者・外部待ち)で停止する |
| SLO | サービス提供側の内部目標(可用性・レイテンシ等) |
| Error Budget | SLOの許容違反量 |

## Identity・認可

| 用語 | 定義 |
|---|---|
| IdP | Identity Provider。Okta / Microsoft Entra ID |
| OIDC | OpenID Connect。**認証**(この人が誰か)のための仕組み |
| SCIM | System for Cross-domain Identity Management。**Provisioning**(ユーザ・グループの作成/更新/無効化)の標準。OIDCとは目的が異なる |
| JIT | Just-In-Time。初回SSO時にユーザを自動作成すること。SCIMの代替にはならない |
| issuer / subject | IdPが発行する識別子の組。SOLVIの人物同定はこの組で行い、メールアドレスでは行わない |
| externalId | SCIMでIdP側が付与する識別子 |
| Organization | グループ会社・組織単位のデータ境界。SOLVIの最重要の分離単位 |
| Role | platform_admin / org_admin / agent / approver / auditor / platform_auditor / requester |
| RoleBinding | ユーザ×ロール×Organizationの割当。期限を持てる(兼務・出向を表現) |
| RLS | Row Level Security。PostgreSQLの行単位アクセス制御。SOLVIでは越境の**安全網**として必須 |
| JML | Joiner / Mover / Leaver。入社・異動・退職のライフサイクル |
| SoD | Segregation of Duties(職務分掌)。申請者と承認者、承認者同士を別人にする統制 |
| Break Glass | 通常経路が使えない緊急時に限定特権を行使する手順。使用自体がインシデント扱い |

## 自動化・監査

| 用語 | 定義 |
|---|---|
| Workflow Run | 申請から承認・実行・通知までの永続化された処理状態 |
| Outbox | 業務状態の変更と同一トランザクションで書くイベント表。Workerが配送する |
| Command | Executorへ渡す型付き・署名付き・期限付きの実行指示 |
| Allowlist | 実行を許可するAction TypeとResourceの一覧。変更には二重承認が必要 |
| Idempotency Key | 同一要求の二重実行を防ぐ決定的に生成されるキー |
| Execution Receipt | 実行対象・事前状態・結果・外部応答・時刻の証跡 |
| Precondition | 実行直前に確認する外部・内部の状態条件 |
| Dry Run | 外部への書込みを行わず、検証だけを本番と同一経路で実施すること |
| Compensation | 誤った操作の打ち消し。SOLVIでは**自動実行せず**、新規の承認済みWorkflowとして行う |
| Kill Switch | 機能を緊急停止するスイッチ(AI用とExecutor用がある) |
| Audit Event | append-onlyの監査記録。[[02.17_Audit_Event_Catalog]]で定義 |
| Correlation ID | 1つの業務フローを横断して追跡するための識別子 |
| Anchor(監査アンカー) | 日次の連鎖ハッシュを外部の改変不能ストレージへ書き出したもの |
| Evidence | Gate判定・監査に使う証跡(コマンド・結果・時刻・commit SHA) |

## AI

| 用語 | 定義 |
|---|---|
| Advisory-only | AIは提案し、人間または決定論的ルールが確定する方針 |
| RAG | Retrieval-Augmented Generation。ナレッジを検索して回答の根拠にする方式 |
| Citation(引用) | AI回答の根拠となった記事とそのバージョン |
| Answerability | 「答えられるかどうか」の判定。根拠がなければ推測せず「わからない」と返す |
| Prompt Injection | 入力データに含まれる指示文でAIを誤動作させる攻撃。間接(記事・チケット経由)を含む |
| AI Trace | プロンプト・モデル・参照文書・応答の記録。監査イベントとは別ストア |
