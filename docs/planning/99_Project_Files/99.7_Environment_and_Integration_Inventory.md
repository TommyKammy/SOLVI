# Environment and Integration Inventory

環境と外部連携の棚卸し。**Gate 0のG0-9**は本表の「確保状況」がすべて確定していることを求める。

## 1. 環境

| 環境 | 用途 | 基盤 | 確保状況 | 所有者 |
|---|---|---|---|---|
| local | 開発 | Docker Compose(PostgreSQL / MinIO / 各サービス) | 要構築(WP-P1-PLAT-001) | Tech Lead |
| dev | 結合・CI | ECS on Fargate(最小構成) | **未確保 — Gate 0までに確認** | Tech Lead |
| stage | Gate検証・UAT | 本番同等構成(データは合成) | **未確保 — Gate A前までに確認** | Ops |
| prod | 本番 | ECS on Fargate + RDS Multi-AZ + S3 | **未確保 — Gate B前までに確認** | Ops |

- 同一イメージをdigest指定で dev → stage → prod へ昇格させる([[ADR-0018_Deployment_Baseline]])。
- 本番のDB・Secretを開発で使用しない。開発環境に実PIIを持ち込まない。

## 3. 未検証事項の扱い

本表の「未検証事項」は、**確定事項として実装の前提にしない**(AGENTS.md §4)。該当WPの開始時に公式ドキュメントとテスト環境で確認し、結果を`10_Research`配下の該当ノートとADRへ反映する。確認できない場合は実装を止めて報告する。

## 4. 資格情報の管理

すべて[[ADR-0016_Secret_Management]]の用途別パスで管理する。テスト環境と本番の資格情報を分離し、Executor用の資格情報はCore/AIのIAMロールから読めないようにする。Secret一覧(用途・保管先・ローテーション周期・所有者)はWP-P1-PLAT-001の成果物として作成する。
