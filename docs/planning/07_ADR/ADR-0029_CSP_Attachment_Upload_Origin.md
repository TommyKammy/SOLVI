# ADR-0029: CSPの connect-src に添付アップロード先(Object Storageのバケット)を加える

## Status

**ACCEPTED**(2026-11-17 起票、同日に利用者(人間)が承認 / Owner: SOLVI Product Team)

- Amends: [[ADR-0027_Browser_Security_Headers]] §2 の `connect-src` だけ。ADR-0027 のほかの決定は変えない。
- Supersedes: なし
- Superseded by: なし
- 2026-11-17 に利用者(人間)が、末尾の「判断が必要な事項」の3点をすべて推奨のとおり決定し、ADR全体を `accepted` とした: 添付用バケットのパスに限ったソースを加える / 値はストレージの設定から組み立て、CSP専用の設定は作らない / 不正・未設定のときは何も加えない(fail closed)。

## Context

- [[ADR-0027_Browser_Security_Headers]] §2 は `connect-src 'self'` とし、外部オリジンは後継ADRで加えると決めた。
- [[WP-P2-SEC-025]] の実装中(2026-11-17)、Report-Only のCSPで主要導線を実画面で検査したところ(`tools/ui_security_headers_check.mjs`、Chromium と WebKit)、**添付のアップロードだけが `connect-src` 違反になった**。ほかの導線(ログイン、ポータル、チケット一覧・詳細・起票、承認の受信箱、ナレッジ検索、申請状況)の違反は0件だった。
- 原因は添付の設計にある:
  - 添付の本体は S3 互換の Object Storage に置く([[ADR-0010_S3_Compatible_Attachments]])。
  - ブラウザは、API が発行した署名付きURL(有効期限10分以内、単一オブジェクト)へ**直接 `PUT` する**(`apps/web/src/components/AttachmentForm.tsx`)。この送信は `fetch` なので `connect-src` の対象になる。
  - 送り先は web とは別のオリジンである(ローカルは SeaweedFS の `http://127.0.0.1:9100`、本番は S3。[[ADR-0028_Local_Object_Storage_Replacement]])。
  - ダウンロードは、web の `/attachments/[id]` が署名付きURLへ 302 で転送する**画面遷移**で、`connect-src` の対象にならない。
- 2026-11-17 時点の事実(署名付きURLの形):
  - `packages/shared/src/storage/object-storage.ts` は、署名付きURLを常に**パス形式**(`<endpoint>/<bucket>/<key>`)で作る。接続先は `S3_PUBLIC_ENDPOINT`、無ければ `S3_ENDPOINT` である。
  - 本番で S3 のリージョンのエンドポイント(例: `https://s3.ap-northeast-1.amazonaws.com`)を使うと、そのホスト名は**すべての AWS 利用者のバケットで共有される**。オリジンだけを許可すると、XSS が入ったときに、攻撃者が自分のバケットへの署名付きURLを使ってデータを持ち出せてしまう。
- 制約: ADR-0027 §6(CSPを無効化・緩和する環境変数や機能フラグを本番に残さない、利用者由来の値からCSPを組み立てない)を守ること。依存パッケージを増やさないこと。強制モードへ切り替えても添付のアップロードが動くこと。

## Decision

### 1. 加えるもの

`connect-src` に、**添付用バケットのパスに限ったソースを1つだけ**加える。

```
connect-src 'self' <アップロード先のオリジン>/<添付用バケット名>/
```

- 例(本番、パス形式の S3): `connect-src 'self' https://s3.ap-northeast-1.amazonaws.com/solvi-attachments/`
- 例(ローカル): `connect-src 'self' http://127.0.0.1:9100/solvi-attachments/`
- CSP のソースにパスを書くと、ブラウザはそのパスの下への接続だけを許す。同じホストの別のバケット(`/<他人のバケット>/…`)への `PUT` はブロックされる。
- `connect-src` 以外(`img-src`、`form-action` 等)には加えない。

### 2. 値の出どころ

- 値は、API が署名付きURLを作るのと**同じデプロイ設定**から web が組み立てる。新しいCSP専用の設定は作らない。
  - アップロード先 = `S3_PUBLIC_ENDPOINT`(無ければ `S3_ENDPOINT`)のオリジン
  - バケット = `S3_BUCKET_ATTACHMENTS`
- これらは**ストレージの接続設定**であり、CSPを無効化・緩和するスイッチではない。CSPを止めたり別のディレクティブを緩めたりはできず、決まった形のソースを1つ加えるだけである。ADR-0027 §6 の「緩和する環境変数」には当たらないと判断する。変更はデプロイ設定の変更として、レビューの対象にする。
- 利用者由来の値(チケット本文、リクエストのヘッダー・クエリ等)からは組み立てない。

### 3. 値の検査(不正なら加えない)

web は値を次のとおり検査し、**1つでも満たさなければ何も加えない**(`connect-src 'self'` のまま。アップロードは失敗するが、CSPは緩まない)。あわせて、エラーをログに出す(値そのものはログに出してよい。Secretではない)。

- URL として解釈でき、ユーザー情報・クエリ・フラグメントを含まない。オリジンだけを使う(エンドポイントのパスは捨てる)。
- 本番(`NODE_ENV=production`)では `https:` に限る。`http:` は、開発時のループバック(`localhost`、`127.0.0.1`、`[::1]`)に限る。
- ホスト名にワイルドカード(`*`)を含まない。
- バケット名は S3 の命名規則(`^[a-z0-9][a-z0-9.-]{1,61}[a-z0-9]$`)に合う。
- 組み立てたソースは、必ず末尾が `/<バケット名>/` になる(パスの無いオリジンだけのソースにしない)。

### 4. 適用の順序

- 本ADRが `accepted` になってから [[WP-P2-SEC-025]] で実装する。WPの Allowed Paths と受け入れ基準は、その時点で更新する。
- 実装後、Report-Only で添付のアップロードを含む主要導線の違反が0件であることを確かめてから、ADR-0027 §4 のとおり強制モードへ切り替える。

## Consequences

### 得られるもの

- 強制モードのCSPの下でも、添付のアップロードが今の設計のまま動く。
- XSSが入っても、ブラウザから接続できる外部は、自分たちの添付用バケットの下だけに限られる。共有のS3ホスト上の他人のバケットへは送れない。
- 値をストレージの設定から組み立てるため、署名付きURLの発行先とCSPの許可先が食い違いにくい。

### 受け入れるコスト

- 添付用バケットへの書き込みは、XSS の経路からも試みられる。ただし書き込みには、API が認可を検査したうえで発行する、単一オブジェクト・10分以内の署名付きURLが必要である(T-16)。署名なしの書き込みは、非公開バケットが拒否する。
- web のデプロイ設定に、ストレージの接続先とバケット名(API と同じ値)が必要になる。設定が無い・誤っている環境では、アップロードが失敗する。
- CSP のパス制限は、リダイレクトの後の接続には効かない(CSP の仕様)。S3 の `PUT` はリダイレクトしない前提で受け入れる。
- 将来、バケット固有のホスト名(仮想ホスト形式や独自ドメイン)へ移る場合は、ソースの形を見直す。

## Rejected Alternatives

- **ストレージのオリジンだけを許可する(パスを付けない)** — パス形式の S3 では、ホスト名が全利用者のバケットで共有される。XSS から他人のバケットへの持ち出しを許してしまう。
- **web を経由してアップロードする(web がストレージへ中継する)** — `connect-src 'self'` のまま済むが、添付の設計(サイズ上限、ウイルス検査の流れ、web の負荷、タイムアウト)を変えることになり、ADR-0010 の見直しが必要になる。CSP のために選ぶには影響が大きい。
- **署名付きURLを仮想ホスト形式(`<bucket>.s3.<region>.amazonaws.com`)へ変え、そのホストを許可する** — 許可の単位としては最も明確だが、`object-storage.ts` の署名処理とローカル(SeaweedFS)の構成を変える必要がある。現時点ではパス制限で同じ効果が得られるため見送る。Follow-up で再判断する。
- **CSP専用の設定(例: `CSP_CONNECT_SRC`)を設ける** — 任意のソースを足せる設定は、ADR-0027 §6 の禁じる「緩和する環境変数」になり得る。ストレージの設定から決まった形で組み立てるほうが安全である。
- **添付だけ CSP を Report-Only のままにする** — CSP はページ単位であり、一部の接続だけを観察モードにはできない。

## Security Impact

- 対応する脅威: T-27(XSS による情報の抜き取り)の緩和を、添付のアップロードを壊さずに強制モードへ進めるための決定である。T-16(署名付きURLの漏えい)の扱いは変えない。
- `connect-src` に外部のソースが1つ増える。範囲は添付用バケットのパスの下に限り、書き込みには認可済みの署名付きURLが要る。
- 信頼境界・権限・RLS・監査・Executor境界・Secretの扱いは変えない。署名付きURLの有効期限(10分以内)と発行時の認可も変えない。
- 違反の記録に署名付きURLを残さない。実画面の検査ツールは、違反のURLをオリジンだけにして記録する(2026-11-17 に対応済み)。
- 新しい依存パッケージを追加しない。

## Operational Impact

- web のデプロイ設定に `S3_PUBLIC_ENDPOINT`(または `S3_ENDPOINT`)と `S3_BUCKET_ATTACHMENTS` を、API と同じ値で渡す。[[08.1_Deployment_Runbook]] に追記する。
- 値が誤っていると、強制モードでは添付のアップロードだけが失敗する。切り分けは、ブラウザのコンソールの `connect-src` 違反と、web のエラーログで行う。切り戻しは ADR-0027 のとおり Report-Only へ戻すデプロイで行う。
- バケット名やストレージの接続先を変えるときは、API と web を同じデプロイで変える。

## Migration Impact

なし(スキーマ・データ・Freshservice移行に影響しない)。

## Follow-up

- [[WP-P2-SEC-025]]: 本ADRの `accepted` 後に、Allowed Paths(web のデプロイ設定の受け渡し)と受け入れ基準(添付のアップロードで違反0件、他人のバケットへの `PUT` がブロックされること)を更新して実装する。
- バケット固有のホスト名(仮想ホスト形式・独自ドメイン)への移行: 本番のストレージ構成を決めるとき([[ADR-0018_Deployment_Baseline]] の実装時)に再判断する。
- ダウンロード(302 の画面遷移)を `img`・`iframe` 等で表示する機能を足す場合は、そのディレクティブへの追加を改めてADRで判断する。

## Verification

- 単体テスト: 値の検査(本番での `http:` の拒否、ワイルドカード・クエリ・不正なバケット名の拒否、不正なら何も加えないこと)。組み立てたソースが `/<バケット名>/` で終わること。本番の `script-src` が変わらないこと。
- 実画面の検査(`tools/ui_security_headers_check.mjs`): 添付のアップロードを含む主要導線で違反が0件であること。同じホストの別のバケットのパスへの `fetch` が `connect-src` 違反になること。
- PRレビュー: セキュリティ関連のPRとして人間のレビューを必須とする(AGENTS.md §1.16)。

## 判断した事項(2026-11-17 利用者決定)

1. 上記のとおり、**パスで添付用バケットに限ったソース**を `connect-src` に加える。
2. 値をストレージの設定(`S3_PUBLIC_ENDPOINT` / `S3_ENDPOINT` と `S3_BUCKET_ATTACHMENTS`)から組み立て、CSP専用の設定は作らない。
3. 値が不正・未設定のときは、何も加えずアップロードを失敗させる(fail closed)。起動自体を止める案は、添付以外の機能まで止まるため採らない。
