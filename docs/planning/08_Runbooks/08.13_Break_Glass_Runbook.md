# Break Glass Runbook

通常経路が使えない緊急時に、限定された特権を一時的に行使するための手順。**使用そのものがインシデントとして扱われ、事後レビューが必須**である。

## 1. 適用条件

- **使う**: ①IdP障害でOIDCログインができず、業務継続に管理操作が必要 ②Executorの異常で自動化を止められない ③重大インシデントでデータ復旧の緊急権限が必要
- **使わない**: 通常の運用作業、権限申請が面倒という理由、テスト目的。これらは通常の承認経路を使う。

## 2. 前提

- 対象アカウント/資格情報: Break Glass用アカウント(通常は無効化)、および一時昇格用のIAMロール
- 保管: 資格情報は封緘保管(パスワードマネージャの分離保管庫 + オフライン控え)。**2名で分割保管**し、単独では使用できない
- 必要な承認: **使用前に2名以上**(Platform Admin + Product OwnerまたはSecurity Reviewer)。連絡不能時は§4.1の例外手順
- 影響: 通常の権限統制が一時的に迂回されるため、全操作が監視対象になる

## 3. 判断基準

| 状況 | 通常経路 | Break Glassの要否 |
|---|---|---|
| IdP障害だが業務は継続できる | 待機 | 不要 |
| IdP障害で承認・実行が完全に停止し、業務影響が大きい | なし | **要** |
| Executorが暴走しKill Switchも効かない | Kill Switch | **要**(サービス停止権限) |
| データ復旧で一時的なDB権限が必要 | なし | **要**([[08.2_Backup_and_Restore_Runbook]]と併用) |

判断に迷う場合は、まず影響の封じ込め(サービス停止・Kill Switch)を試み、それでも解決しない場合にのみ使用する。

## 4. 手順

### 4.1 使用の承認

1. 使用理由・想定操作・想定所要時間を記録する(口頭でも必ずテキスト化)。
2. 承認者2名の同意を得る。連絡不能時は**単独実行を許容するが**、実行内容を逐次記録し、事後4時間以内に報告する。
3. 使用開始時刻を記録し、関係者へ通知する(Slack等の記録が残るチャネル)。

### 4.2 資格情報の取り出し

1. 封緘保管から取り出す(2名立会い、可能であれば画面共有しながら)。
2. 取り出した事実を記録する。

### 4.3 操作の実行

1. **事前に決めた操作のみ**を行う。範囲外の操作を「ついでに」行わない。
2. 全操作をコマンド履歴または画面録画として記録する。
3. 操作ごとに実施時刻と結果を記録する。

### 4.4 終了処理(必須。使用当日中に完了させる)

1. Break Glassアカウントを再度無効化する。
2. **使用した資格情報をローテーションする**([[08.7_Executor_Credential_Rotation]])。使用後の資格情報は失効させる。
3. 一時付与したIAM権限を剥奪する。
4. 封緘を再作成し、保管する。
5. 監査イベント`breakglass.used`が記録されていることを確認する。記録されていない場合は手動で監査記録を作成し、その旨も記録する。

## 5. 検証

- [ ] Break Glassアカウントが無効化されている
- [ ] 使用した資格情報がローテーションされ、旧値で認証できない
- [ ] 一時付与の権限が剥奪されている(IAM確認)
- [ ] 実施した操作の一覧と結果が記録されている
- [ ] 想定範囲外の操作が行われていない(操作ログのレビュー)
- [ ] 通常経路が復旧している

## 6. ロールバック

Break Glassで行った変更が誤りだった場合は、通常経路が復旧した後に**通常の承認経路で**是正する。Break Glassを再使用して是正しない。

## 7. 証跡(記録すること)

- 使用理由、承認者2名(または単独実行の理由)
- 開始・終了時刻、実施者
- 実行した全操作と結果
- ローテーションした資格情報の一覧と実施時刻
- 事後レビューの実施日と結論

## 8. 事後対応(使用後5営業日以内)

- [ ] Security Reviewerによる事後レビューを実施する(操作の妥当性、範囲逸脱の有無)
- [ ] Break Glassが必要になった根本原因を分析し、次回は通常経路で対応できるよう改善する
- [ ] 結果を[[99.3_Risk_Register]]と[[99.4_Decision_Log]]へ記録する
- [ ] この手順の不足点を反映する

## 9. 演習

**年2回**、実際に資格情報を取り出す演習を行う(操作は読取のみ)。演習後もローテーションを実施する。Gate B(GB-6)で初回の机上演習を行う。
