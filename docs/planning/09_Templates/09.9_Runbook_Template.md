# Runbook Template

Runbookは「手順名の列挙」ではなく、**当事者が深夜に読んで実行できる**粒度で書く。

```markdown
---
project: SOLVI
doc_id: "08.n"
title: "<対象事象> Runbook"
category: "08_Runbooks"
type: "runbook"
status: "baseline"
version: "0.1.0"
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
owner: "<一次対応者の役割>"
tags: ["runbook"]
source_of_truth: true
implementation_status: "not-started"
---

# <対象事象> Runbook

## 1. 適用条件(このRunbookを使う場合/使わない場合)
- 使う: <具体的な症状・アラート名・エラーメッセージ>
- 使わない: <似ているが別Runbookを使うケースとその参照先>

## 2. 前提
- 必要な権限: <ロール名。Break Glassが必要な場合は明記>
- 必要なアクセス: <環境・ツール・URL>
- 所要時間の目安: <分>
- 影響範囲: <この対応中に利用者が受ける影響>

## 3. 判断基準(トリアージ)
| 観察される状態 | 判定 | 進む手順 |
|---|---|---|
| <条件> | <重大度> | §4.x |

判断できない場合の既定動作を必ず書く(原則: 安全側=停止・拒否)。

## 4. 手順
### 4.1 <段階名>
1. <実行するコマンドまたは操作>
   ```bash
   <コマンド>
   ```
   期待される結果: <出力例>
   想定外の場合: <分岐先>

※ 各手順に「期待される結果」と「想定外の場合」を書く。コマンドだけを並べない。

## 5. 検証(復旧したことの確認)
- [ ] <確認項目と合格条件>
- [ ] 二重実行・越権・証跡欠落が発生していないこと

## 6. ロールバック(この対応が悪化させた場合)
<戻し方。戻せない場合はその旨と次の手段>

## 7. 証跡(記録すること)
- 検知時刻 / 対応開始 / 復旧時刻
- 環境・Organization・関連ID(Ticket / Workflow Run / Command / Receipt)
- 実行したコマンドと結果(Secretを除く)
- 判断者・承認者・外部ケースID
- 残存リスクとフォローアップ

## 8. 事後対応
- [ ] 必要ならPIR、[[99.3_Risk_Register]]、ADR、WPを更新
- [ ] 手順の不備をこのRunbookへ反映
- [ ] 演習で発見した問題も同様に反映

## 9. 演習
最終演習日: YYYY-MM-DD / 実施者: <名前> / 結果: <所要時間・問題点>
（Gate条件に演習が含まれるRunbookは、演習記録なしにGateを通過させない）
```

## Runbookの品質基準

- [ ] 適用条件と非適用条件が書かれている
- [ ] 判断基準が表になっており、判断不能時の既定動作がある
- [ ] コマンドに期待結果と想定外時の分岐がある
- [ ] 検証項目に「二重実行・越権・証跡欠落の不在」が含まれる
- [ ] 証跡の記録項目が具体的である
- [ ] 演習記録の欄がある
