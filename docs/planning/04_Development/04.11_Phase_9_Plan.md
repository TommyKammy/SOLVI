| 項目 | 値 |
|---|---|
| Phase | P9 |
| 期間(初期見積り) | 7〜10週間 |

| Exit | [[04.22_Gate_Definitions]] Gate C |

## 1. このPhaseで達成すること

- 移行設計とdry-run(2回以上)
- 並行稼働と件数・ハッシュ照合
- 本番運用とRestore Game Day
- 教育と問い合わせ導線の移管
- Build/Hybrid/Buyの判断

## 3. このPhaseでやらないこと

- 判断前の全面切替(並行稼働とGate C判定が先)

## 4. Exit条件

[[04.22_Gate_Definitions]]の **Gate C** のチェックリストをすべて満たすこと。判定者はProduct Owner + Security Reviewer。

- 未達項目があるまま次Phaseの高リスク作業へ着手しない。
- Critical/Highの未解決が0件であること。
- 対象WPがすべて[[04.19_Definition_of_Ready_and_Done]]のDoDを満たすこと。

## 5. リスクと対策

- **スケジュール圧力**: Gate未達なら期間を延ばす。合格条件を緩めない([[04.1_Master_Roadmap]]§3)。
- **依存の未完了**: 着手条件を満たさないWPは着手しない(AGENTS.md §2.2)。
- **見積り乖離**: Phase完了時に計画と実績のポイント/期間を記録し、次Phaseの見積りへ反映する。
