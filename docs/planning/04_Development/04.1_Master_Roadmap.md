- Phase 0を「文書承認」ではなく「設計実体の作成」として再定義した(ADR実体化・脅威モデル・Gate定義・WP実体化)
- Phase 1にバックアップ/リストア実演(WP-P1-BCK-007)を追加した
- Phase 2にSLO/オンコール整備(WP-P2-SLO-008)を追加した
- Phase 4のExecutorを3WPへ分割し、契約検証・冪等・Retry/KillSwitchを個別に検証する構成にした
- 人間のレビュー・UAT・セキュリティ検証・Gate判定の時間をクリティカルパスに含めた

## 2. 見積りの前提と較正

- Story PointはCodexの処理時間ではなく、**レビューと検証を含む複雑性**である。
- ポイント→期間の換算はPhase 0/1の実績で較正する。Gate 1時点で計画と実績の乖離をレビューし、P2以降を再見積りする。
- 1つのPhaseで並行して進められるWPは[[06.1_Dependency_Map]]の「並行実行可能な単位」を参照する。実際の並行度はレビュー能力(人間側)が律速になる。

## 3. 進行原則

- 前PhaseのGate未達で、次Phaseの高リスク作業(特権操作・SCIM・本番移行)へ着手しない。
- UI・API・認可・監査・運用を**縦切りで**完成させる。横断的な作り置きをしない。
- Codexの実装速度を理由に、Security Review・UAT・Restore Drillを省略しない。
- **期間よりExit Criteriaを優先する。** 期限に合わせて合格条件を緩めない。

## 4. マイルストーン

M0 設計正本の承認 → M1 基盤セキュリティ(OIDC/RLS/監査/復旧) → M2 チケットMVP → M3 ナレッジ → M4 申請・承認・特権自動化 → M5 SCIM → M6 資産 → M7 変更 → M8 AI → M9 置換判断
