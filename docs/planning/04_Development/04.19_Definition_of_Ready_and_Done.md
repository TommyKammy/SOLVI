# Definition of Ready and Done

曖昧な着手と、Evidenceのない完了を防ぐための基準。

## 1. Definition of Ready(着手してよい状態)

WPが以下をすべて満たすとき、Issue化して着手できる。1つでも欠けていれば着手しない。

- [ ] WPの`status`が`baseline`である(`draft`は着手不可 — AGENTS.md §0)
- [ ] Requirement IDが記載され、[[03.18_Requirements_Traceability_Matrix]]と一致している
- [ ] Dependenciesが記載され、**すべて完了している**
- [ ] Allowed Pathsが実在するパスを指している
- [ ] Out of Scopeが具体的である(「後続Phaseの機能」だけで終わっていない)
- [ ] Acceptance Criteriaが検証可能である(「誰が何をすると何が起きる」が判定できる)
- [ ] 参照する設計文書が存在し、`status`が`baseline`以上である
- [ ] Rollback/失敗時の扱いが書かれている
- [ ] Codex Promptがこのwork package固有の内容になっている

## 2. Definition of Done(完了と認めてよい状態)

- [ ] Acceptance Criteriaをすべて満たし、各項目に対する**証拠**がある
- [ ] リスクに応じたテストが通っている([[04.16_Test_Strategy]]のTL-ID指定)
- [ ] **本番経路から呼ばれている**(`npm run check:unwired` が通る)
- [ ] **稼働中のスタックで実際に動くことを確認した**(`verify_*` / `e2e/*`、または
      それに相当する実経路での確認。テスト補助を使わないこと)
- [ ] DB変更にMigration(up/down)、ロールバック方針、既存データ互換の説明がある
- [ ] 関連ドキュメント(API定義、Runbook、RTM、Architecture)を更新した
- [ ] 未解決のCritical/Highがない
- [ ] Evidenceを`evidence/<WP-ID>/<YYYYMMDD-HHMM>/`へ保存した
- [ ] Execution Logへ結果を追記した
- [ ] 必要なsign-offを得た(下表)

### リスク別の追加要件

| Risk | 追加で必要なもの |
|---|---|
| low | 通常のPRレビュー |
| medium | 上記 + テスト結果のEvidence |
| high | 上記 + Tech Leadのレビュー + 異常系テストのEvidence |
| critical | 上記 + **Security Reviewerのsign-off** + 攻撃観点テスト + 演習記録(該当する場合) |

Identity・Security・Executor・Migration・監査に関わるWPは、Riskに関わらずSecurity Reviewerのsign-offを必須とする([[06.0_WorkPackage_Register]])。

## 3. Doneにしてはいけないケース

- テストが落ちている、またはskipで通している
- Acceptance Criteriaのうち「後で対応」が残っている
- Evidenceが「動作を確認した」という記述のみで、コマンド・結果・時刻がない
- 一時的な例外(認可バイパス、RLS無効化、検証スキップ)がコードに残っている
- 設計判断を自分で決めて進めた箇所がある(ADRまたはOpen Questionへ記録していない)
- **テストは緑だが、その機能を呼ぶ本番経路が無い**

> [!warning] 「テストが緑」は本番で動く根拠にならない
> [[WP-P2-NTF-005]](通知)と [[WP-P1-AUD-004]](監査アンカー)は、
> 受入基準をすべて満たし「実装済み」とされながら、
> **本番経路から一度も呼ばれていなかった。**
> テストが自分でイベントを積み、自分でバッチを起動していたためである。
>
> 受入基準が「正しく振る舞うこと」だけを問い、
> **「その振る舞いが発生する経路を持つこと」を問うていなかった。**
> 経緯は [[04.23_Wiring_Verification]]。

## 4. Reopen(完了後の差し戻し)

以下のいずれかが判明した場合、WPをReopenして修正する。新しいWPを作って先送りしない。

- Acceptance Criteriaの解釈違いにより、意図した検証がされていなかった
- 同一WPのスコープ内で、後から重大な不具合が見つかった
- Gate判定でそのWPに起因する不合格が出た
