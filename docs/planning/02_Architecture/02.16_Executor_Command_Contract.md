# Executor Command Contract

SOLVI Run(Privileged Executor)の入出力契約の正本。[[ADR-0006_Privileged_Executor_Separation]]の実装仕様であり、WP-P4-EXEC-004系の受入基準は本書の節番号を参照する。

## 1. Command スキーマ(v1)

```json
{
  "command_id": "uuid v7(発行時にWorkflowが採番)",
  "schema_version": "1",
  "action_type": "okta.group.add_member",
  "target": {
    "connector": "okta",
    "resource_type": "group_membership",
    "resource_id": "許可済みGroupの内部参照ID(外部IDの直接指定は禁止)",
    "subject_id": "対象UserのSOLVI内部ID"
  },
  "idempotency_key": "§4の規則で生成",
  "approval_ref": { "approval_id": "...", "decided_at": "...", "policy_version": "..." },
  "workflow_run_id": "...",
  "organization_id": "...",
  "requested_by": "起票ユーザの内部ID",
  "issued_at": "RFC3339",
  "expires_at": "issued_at + 15分(上限。超過Commandは無条件拒否)",
  "nonce": "128bit乱数(再利用拒否)",
  "dry_run": false
}
```

- **署名**: Command全体をJWS(Ed25519)で署名。鍵はWorkflow Orchestrator専用のKMS鍵。Executorは公開鍵で検証し、`kid`未知・署名不一致・`expires_at`超過・`nonce`再利用(§4のストアで判定)をすべて**無条件拒否**する。
- **外部IDの直接指定禁止**: `resource_id`はSOLVI DB内のAllowlistレコードIDであり、Okta/Entraの生IDをCommandに載せない。Executorが実行直前にAllowlistレコード→外部IDを解決する(チケット本文由来の値が特権操作パラメータへ到達する経路を遮断)。

## 2. Action Type Allowlist

| action_type | connector | 必要スコープ | リスク | Phase |
|---|---|---|---|---|
| okta.group.add_member | okta | okta.groups.manage | High | P4 |
| okta.group.remove_member | okta | okta.groups.manage | High | P4 |
| entra.group.add_member | graph | GroupMember.ReadWrite.All(要縮小検討: PIM/管理単位) | High | P4 |
| entra.group.remove_member | graph | 同上 | High | P4 |
| okta.user.create | okta | okta.users.manage | Critical | P5以降(Gate B実績後) |

- Allowlistは`executor_allowed_action`/`executor_allowed_resource`テーブル(PostgreSQL)で管理。**変更はSOLVI Ops上で二重承認(管理者2名)+監査イベント必須**。ファイル・環境変数での定義は禁止(変更が監査に乗らないため)。
- 未知の`action_type`・Allowlist外の`resource_id`・無効化済みAllowlistエントリは拒否し、`policy_violation`として監査記録。

## 3. 実行前検証(Executor内、実行直前に毎回)

順序固定。いずれか失敗で実行せず拒否Receiptを返す:

1. スキーマ・署名・期限・nonce検証(§1)
2. Allowlist照合(§2)
3. **承認の再検証**: Core APIの読取専用エンドポイントで`approval_ref`の現在状態を照会 — approved・未失効・未取消・**承認後に申請内容が変更されていない**(FR-CAT-008のsnapshot hash一致)こと
4. SoD検証: 実行対象subjectと承認者が同一人物でない(FR-CAT-007/010)
5. 事前条件(Precondition): 外部の現在状態を取得(例: 既にメンバーか)。冪等的にno-opになる場合はそれをReceiptへ記録して正常終了

## 4. 冪等性

- **Idempotency Key生成規則**: `sha256(workflow_run_id + step_id + action_type + resource_id + subject_id)`。リトライ・再送でも同一Keyになる決定的生成。
- Executorは`execution_receipt`テーブルへKeyのUNIQUE制約付きで**実行前にINSERT(status=in_progress)**。INSERT競合=既実行/実行中として、既存Receiptを返す(二重配送・並行配送に安全)。
- `in_progress`のまま一定時間(アクション別、既定10分)経過したものは「結果不明」とし、自動再実行せず[[08.6_SOLVI_Run_Failure]]の人間判断へ回す。

## 5. Receipt スキーマ(v1)

```json
{
  "receipt_id": "uuid v7",
  "command_id": "...", "idempotency_key": "...",
  "organization_id": "...", "workflow_run_id": "...", "approval_ref": {...},
  "status": "succeeded | noop | rejected_policy | rejected_precondition | failed_retryable | failed_permanent | unknown",
  "pre_state": "実行前の外部状態(例: member=false)",
  "post_state": "実行後の外部状態(検証読取の結果)",
  "external_request_id": "Okta/Graphのrequest id",
  "external_response_summary": "ステータスコード+本文要約(Secret/PII除去)",
  "attempts": 1,
  "started_at": "...", "finished_at": "...",
  "executor_version": "git SHA", "policy_version": "評価時のAllowlist/Policyバージョン"
}
```

Receiptはappend-only。TicketとWorkflow RunのUIから参照可能にする(FR-AUT-005)。

## 6. エラー分類とRetry / Compensation

| 分類 | 例 | 扱い |
|---|---|---|
| rejected_policy | Allowlist外、署名不正、SoD違反 | Retryしない。監査+Security通知 |
| rejected_precondition | 承認取消済み、対象不存在 | Retryしない。Workflowへ差戻し |
| failed_retryable | 429(Rate Limit)、5xx、ネットワーク | `Retry-After`尊重。指数バックオフ、最大5回。**Retryも同一Idempotency Key** |
| failed_permanent | 400、権限不足 | Retryしない。Runbook 08.6 |
| unknown | タイムアウト(送信後応答なし) | 自動Retry禁止。外部状態を読取照合してから人間判断 |

- **Compensation**: 逆操作が自明なもの(add⇄remove)は補償Commandを定義するが、**自動補償はしない**。補償は新しい承認済みWorkflowとしてのみ実行(補償自体も監査に乗せる)。

## 7. Dry Run

`dry_run: true`は§3の全検証+事前条件取得まで実施し、外部書込みだけをスキップ。**Policy評価コードは本番と同一パス**(分岐は最終書込み呼出しのみ)であることをテストで担保する(FR-AUT-007)。

## 8. 資格情報・ネットワーク

- Executor資格情報(Okta OAuth service app秘密鍵、Graph client credential)はExecutor専用のSecrets Managerパスに置き、CoreとAIのIAMロールからは読取不能([[ADR-0016_Secret_Management]])。
- ExecutorのEgressはOkta/Graphの必要エンドポイントのみ許可。Ingressは内部ネットワークのWorkflow Dispatcherのみ。AIサービスとの経路は存在させない(Gate B GB-8で検査)。
- **Kill Switch**: `executor_kill_switch`フラグ(DB+環境フェイルセーフの二重)。有効時は全Command受付を拒否しin_progressの新規実行を停止。発動・解除は監査イベント必須。
