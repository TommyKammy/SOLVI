# Observability Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

Log、Metric、Trace、Audit Eventを目的別に分離し、Correlation IDでつなぐ。

## 2. 目的

- 障害解析と監査説明を短時間化

## 3. 対象範囲

- OpenTelemetry
- Structured logs
- SLO
- Alert
- Redaction
- Degraded health

## 4. 対象外

- PII/Token/Ticket本文の無制限Log

## 5. 基本方針

- **Correlation**：Ticket/Workflow/Command/Run IDを連結
- **Audit separation**：運用Logを監査正本にしない
- **Useful alerts**：Actionable alertのみ

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
