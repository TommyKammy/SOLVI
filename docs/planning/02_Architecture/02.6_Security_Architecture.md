# Security Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

OIDC、RBAC/ABAC、Organization境界、Secret分離、Audit、Rate Limit、入力防御を多層化する。

## 2. 目的

- 越権、改ざん、漏えい、二重実行を防ぐ

## 3. 対象範囲

- AuthN/AuthZ
- RLS
- Secret management
- Executor policy
- Redaction
- File security

## 4. 対象外

- Ticket本文を信頼境界とすること

## 5. 基本方針

- **Fail closed**：検証失敗時は拒否
- **Least privilege**：Connectorごとに最小Scope
- **No secret in AI**：Prompt/TraceへSecretを送らない

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
