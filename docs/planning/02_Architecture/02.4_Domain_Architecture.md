# Domain Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

Ticket、Catalog、Approval、Workflow、Execution、Knowledge、Asset、Change、Identity、Auditを境界づける。

## 2. 目的

- ドメイン責務と依存方向を固定する

## 3. 対象範囲

- Aggregate
- State transition
- Domain event
- Reference relation

## 4. 対象外

- 画面からの直接DB更新

## 5. 基本方針

- **Application services**：状態変更の唯一の入口
- **Invariants**：承認済み・未期限切れのみ実行
- **Identifiers**：内部IDと外部IDを分離

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
