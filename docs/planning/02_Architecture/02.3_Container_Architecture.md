# Container Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

実行単位と通信方向を定義し、禁止依存を固定する。

## 2. 目的

- 開発、デプロイ、障害切り分けを容易にする

## 3. 対象範囲

- web
- api
- worker
- ai-advisor
- executor
- postgres
- object storage
- telemetry

## 4. 対象外

- APIから管理APIへの直接書込み

## 5. 基本方針

- **Direction**：Web→API→Outbox→Worker→Executor
- **Credential separation**：Executor資格情報はCoreから参照不可
- **AI access**：制限された読取Contextのみ

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
