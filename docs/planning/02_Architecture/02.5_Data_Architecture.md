# Data Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

現在状態テーブルとappend-only Eventを組み合わせ、完全イベントソーシングなしで監査性を確保する。

## 2. 目的

- 整合性、検索性、監査性を両立

## 3. 対象範囲

- Schema/Migration
- Outbox
- Audit
- Attachment metadata
- Retention

## 4. 対象外

- 監査正本を外部SaaSだけに依存

## 5. 基本方針

- **Transaction**：状態変更とOutboxを原子的に保存
- **Retention**：削除より無効化・匿名化
- **PII**：必要最小属性

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
