# Deployment Architecture

> [!warning] この文書は骨子のみ(status: draft)
> 実装根拠に使用できません(AGENTS.md §0)。**該当機能のPhase着手前**までに[[09.2_WorkPackage_Template]]相当の水準へ実体化します。
> 現時点で確定している内容は、リンク先の`baseline`文書を参照してください。

## 1. 概要

LocalはDocker Compose、本番はAWSコンテナ環境を候補とし、環境分離とSecret管理を行う。

## 2. 目的

- 再現可能な開発環境と本番運用を両立

## 3. 対象範囲

- dev/test/stage/prod
- Registry
- Migration job
- Private network
- Managed PostgreSQL candidate

## 4. 対象外

- 本番DB・Secretの開発利用

## 5. 基本方針

- **Image promotion**：同一Imageを昇格
- **Secret store**：AWS Secrets Manager等
- **Decision pending**：ECS/EKS/EC2はGate 0で確定

## 6. 成果物

- Architecture view
- 責務・依存・禁止経路
- 関連ADR/WP

## 7. 受入基準

- [ ] Trust boundaryが明確
- [ ] 要求と矛盾しない
- [ ] Issueへ分解可能

## 8. リスクと対策

- **Overengineering**：初期はModular Monolithを維持
- **Boundary violation**：Architecture/Security testで検出
