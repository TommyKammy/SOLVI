# Threat Model

資産×侵入口ごとの脅威・対策・検証の正本。Phase 4/5/8の開始前に必ず更新する。各脅威は要求ID(対策)とGate検証項目([[04.22_Gate_Definitions]])へ接続する。

## 1. 保護対象資産(優先順)

1. Executor資格情報(Okta/Graph特権) 2. 承認レコードの完全性 3. 監査ログ 4. Organization境界内の業務データ(チケット・添付・ナレッジ) 5. SCIMトークン/OIDCクライアント資格情報 6. Identity/RoleBinding(権限体系そのもの)

## 2. 脅威マトリクス

| # | 侵入口/面 | 脅威(STRIDE) | シナリオ | 対策(要求/設計) | 検証 |
|---|---|---|---|---|---|
| T-01 | API全般 | Cross-org access(I/E) | 他社Orgのチケット・添付・記事をID列挙で取得 | NFR-SEC-001、[[02.18_Organization_Data_Model_and_RLS]]二層防御 | G1-2/G1-3、越境自動テスト |
| T-02 | API全般 | IDOR/BOLA(E) | 同一Org内で権限外オブジェクト(内部メモ、他人の申請)へ直接ID指定アクセス | NFR-SEC-006(オブジェクトレベル認可)、404優先 | 認可テストスイート、GB-9 |
| T-03 | API全般 | Mass assignment(T) | 申請APIに`status`や`organization_id`を注入し状態改ざん | NFR-SEC-005、DTOホワイトリスト(明示フィールドのみbind) | 契約テスト+GB-9 |
| T-04 | OIDC | 設定不備・トークン偽装(S) | issuer混同、audience未検証、stateなしCSRF、nonce再生 | FR-IDM-001(全検証必須)+PKCE、IdPごとにissuer固定 | G1-1ネガティブテスト |
| T-05 | セッション | 退職者の残存アクセス(E) | IdP無効化後もセッション/リフレッシュで利用継続 | FR-IDM-008(失効SLA 15分以内) | G1-9 |
| T-06 | SCIM | トークン漏えい(S/E) | SCIM Bearer流出→ユーザ作成・ロール改ざんで侵入 | FR-IDM-009(90日ローテ、失効即時)、IdP IP allowlist+専用ホスト、platform roleのSCIM付与禁止(02.18§2) | Gate 5、トークン失効テスト |
| T-07 | IdPグループ改ざん | 権限昇格(E) | IdP側グループ操作でSOLVI管理者権限を奪取 | FR-IDM-003(未知group fail closed)、platform_adminはIdPマッピング禁止 | マッピング制約テスト |
| T-08 | 承認 | 自己承認・偽装承認(S/R) | 申請者が自分で承認/承認レコード偽造/承認後に申請内容を書換え | FR-CAT-007(自己承認禁止)、FR-CAT-008(snapshot hash再検証)、FR-CAT-010(高リスク二重承認+SoD)、承認は監査イベント+相関ID | GB-3 |
| T-09 | Executor | Command偽造・Replay(S/T) | 過去Commandの再送、署名なしCommand注入 | NFR-SEC-010、[[02.16_Executor_Command_Contract]]§1(Ed25519+exp≤15分+nonce) | GB-1 |
| T-10 | Executor | 二重実行(T) | 再送・並行配送で外部変更が複数回 | FR-AUT-003、02.16§4(決定的Key+UNIQUE+in-progress行) | GB-2 |
| T-11 | Executor | 資格情報窃取(I/E) | Core/AI侵害からExecutor Secretへ横移動 | ADR-0006分離、ADR-0016(専用Secretパス+IAM分離)、Egress限定 | GB-7/GB-8 |
| T-12 | Executor | Allowlist改ざん(T/E) | 管理画面/DB直接でAllowlistへ任意グループ追加 | 02.16§2(二重承認+監査必須、ファイル定義禁止) | GB-4 |
| T-13 | AI | Prompt injection(直接/間接)(T/E) | チケット本文・ナレッジ記事内の指示文でAIに越権操作・情報露出を誘導 | FR-AI-005、ADR-0007(AIに書込み権限なし)、コンテキスト分離(データを命令として扱わない)、AI→Executor経路の物理遮断 | Gate 8注入テスト、GB-8 |
| T-14 | AI/RAG | 権限外情報の混入(I) | サービス権限で検索した他Org/Agent限定記事が回答に混入 | 02.18§4(ユーザ権限で検索)、FR-KNW-002 | Gate 3/8 |
| T-15 | 添付 | マルウェア配布(T) | 悪性添付のアップロード→他ユーザDL | FR-TKT-005(スキャン完了まで配布不可、隔離)、実行形式ブロック | GA-3+スキャンテスト |
| T-16 | 添付URL | 署名URL漏えい(I) | 署名付きURLの転送・推測で他Orgが取得 | 02.18§4(≤10分、単一オブジェクト、発行時認可) | GA-3 |
| T-17 | Webhook/通知 | Spoofing(S) | 偽Webhookで状態改ざん、通知経由の機微漏えい | NFR-SEC-007(HMAC署名+timestamp±5分+リプレイ拒否)、通知本文最小化 | 契約テスト、GB-9 |
| T-18 | サーバ側取得 | SSRF(I/E) | URL指定機能(Webhook先等)で内部メタデータへ到達 | NFR-SEC-005、送信先allowlist+プライベートIP帯ブロック | セキュリティテスト |
| T-19 | 監査 | ログ改ざん・削除(T/R) | 管理者/DBAが証跡を消す | NFR-SEC-003+AUD-001、[[02.17_Audit_Event_Catalog]]§3(REVOKE+日次外部アンカー) | G1-4/G1-5、GB-10 |
| T-20 | 内部者 | 管理者の越権閲覧(I) | platform_adminが業務目的外で他Org閲覧 | org切替の監査イベント化(02.18§3)、auditor分離、四半期アクセスレビュー(NFR-SEC-002) | 監査レビュー記録 |
| T-21 | 供給網 | 依存/イメージ汚染(T) | 悪性npmパッケージ、改ざんベースイメージ | NFR-SEC-008(lockfile+脆弱性scan+digest固定+更新レビュー) | G1-6 |
| T-22 | Secret運用 | コミット・ログ漏えい(I) | Secretのgit混入、ログ/AI prompt混入 | NFR-SEC-004(secret scan CI+ログredaction+AI送信禁止) | G1-6、redactionテスト |
| T-23 | バックアップ | バックアップ経路の漏えい(I) | スナップショット/exportの持出し | NFR-SEC-009(暗号化+アクセス制御+復元演習時の取扱手順) | Restore Drill記録 |
| T-24 | 可用性 | DoS/暴走ジョブ(D) | 大量申請・検索・AI呼出しでの資源枯渇 | Rate Limit(02.6)、AIクォータ(RISK-010)、キュー分離 | 負荷テスト(P9) |

## 3. 明示的リスク受容(期限付き)

| ID | 内容 | 理由 | 再評価 |
|---|---|---|---|
| RA-01 | DB内全行ハッシュチェーンは実装しない(日次アンカーのみ) | 書込み性能と複雑性。日次検知で監査要件を満たす | Gate C |
| RA-02 | SIEMリアルタイム連携はPhase 8まで実装しない(export APIで代替) | 初期は監査者の手動照会で十分 | Phase 8 |
| RA-03 | 子Organization階層の閲覧継承は初期非対応 | 要件未確定。分離のほうが安全側 | 要件発生時にADR |
